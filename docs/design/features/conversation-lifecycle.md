# 会話の締めくくりと管理

- 種別: 機能設計書
- 対象 UC: UC-006 (docs/design/USECASES.md)

## 何を作るか

会話を閉じる前に、できたものと残っているものを確かめてから閉じる。閉じた会話はスレッドとともに一覧と検索から探せて、続きを送ると再開する。要らない会話は削除する。

**使う人**: 開発者

**流れ**:

1. 会話で締めくくりの操作をすると、右のウィンドウに成果 (issue、変えたファイル、コミット、PR) と残り (未コミットの変更、未 push のコミット、未送信のストック、動いているスレッド) が出る
2. 確かめて閉じると、会話は一覧から外れる。閉じずに会話へ戻ることもできる
3. 会話とスレッドの一覧か、語の検索で、閉じたものを含めて探す
4. 閉じた会話を開いて続きを送ると、会話が再開して一覧に戻る
5. 要らない会話は、一覧で確認に答えて削除する

**主な決まり**:

- 閉じても、会話の内容・目次・決まったことの一覧は残る (BR-029)
- 閉じても worktree とファイルは消さない (BR-032)
- 閉じても、未送信のストック、送る前の回答、書きかけ、届く前の指示は残り、再開すると元のまま戻る。動いているスレッドの AI は閉じるときに止める (BR-097)
- AI が作業中なら、止めて閉じるか、やめるかを選ぶ
- 閉じた会話は、開いただけでは再開しない。続きを送ると再開する (BR-096)
- 削除は取り消せないので、確認を挟む。会話とそのスレッドをまとめて消す (BR-031)
- 締めくくるのは開発者が始めた会話だけである。issue はプロジェクトの画面で取り下げ、スレッドはスレッドの表示で終える

## 入出力と振る舞い

### この機能の前提

- 閉じた会話とは、`conversations.closed_at` が入った会話である。一覧とツリーには出さない (BR-030。一覧とツリーの作りは `features/inbox.md`)
- 閉じる・開き直すで変わるのは `closed_at` だけで、`run_state` は変えない。`closed_at` は画面のサーバーが書く (`features/runtime.md`「書くプロセスの分担」)
- スレッドを終える・開き直すも同じ `closed_at` で表す。スレッドを終える操作は `features/stock-thread.md` が持つ
- 画面は UI_SKETCH.html の `pc-conv--close` (締めくくり)、`pc-convs` (会話とスレッドの一覧)、`pc-search` (issue と会話の検索) を手本にする。部品は `features/buffer-ui.md` に従う
- 本書のキーとコマンドは `features/buffer-ui.md` の表にある: Space z と `:close` (締めくくる)、Space b と `:convs` (一覧)、Space f と `:find` (検索)

### 締めくくりの確認

Space z を会話で押すと、右のウィンドウ「会話を締めくくる」を開き、`GET /api/conversations/:id/closing-summary` の結果を出す。

| 見出し | 行 | 求め方 |
| --- | --- | --- |
| できたもの | issue | この会話から AI が作った issue。`issues.created_conversation_id` がこの会話の issue |
| 〃 | ファイル | この会話で AI が変えたファイル (`features/files.md`「AI が変えた箇所」と同じ集計) |
| 〃 | コミット | 会話の最初の記録の時刻より後に、作業ディレクトリのいまのブランチにできたコミット |
| 〃 | PR | GitHub を使うプロジェクトで、いまのブランチを head にした PR のうち、会話の開始より後に作ったもの |
| 残っているもの | 未コミット | 作業ディレクトリの、コミットしていない変更のファイル |
| 〃 | 未 push | 上流のブランチに無いコミットの数 |
| 〃 | ストック | 送っていないストックの件数 (指示と質問) |
| 〃 | スレッド | 動いているスレッド (`run_state` が `working` / `waiting_answer` / `waiting_permission`) |

- コミットと PR は、会話ではなく作業ディレクトリから求める。ほかの会話が同じディレクトリでコミットしたものも入るので、見出しの下に「この会話を始めてから、この作業場所でできたもの」と出す
- コミットは `git log --since-as-filter=@<開始後の最初の Unix 秒> --format=%ct%x09%H%x09%s HEAD` で求める。履歴をたどったあと、コミッター時刻の新しい順に並べる
- PR は `gh pr list --head <ブランチ> --state all --json number,title,url,state,createdAt --limit <件数>` で求める。100 件から取得を始め、会話の開始時刻か一覧の末尾に達するまで取得件数を増やす。いまのブランチが既定のブランチなら「なし」とする
- 未コミットは `git status --porcelain` で、未 push は `git rev-list --count @{u}..HEAD` で求める。上流のブランチが無ければ `git rev-list --count HEAD --not --remotes` で数え、「(上流のブランチなし)」を添える
- 作業ディレクトリが Git の管理外なら、コミット・PR・未コミット・未 push の行に「Git の管理外」と出す
- 項目ごとに 10 秒で打ち切る。失敗した項目は「取得できませんでした (<理由>)」と出し、ほかの項目と閉じる操作には影響させない
- 何も無い項目は「なし」と出す
- 最後に「操作」の見出しと、メニューの行「この会話を閉じる」「やめて会話に戻る」を出す。その下に「閉じても、会話の内容・目次・決まったことは残ります。」「worktree とファイルは消しません。」の説明の行を出す
- AI が作業中 (`working` / `waiting_answer` / `waiting_permission`) なら、先頭に「AI が作業中です。閉じるには AI を止めます」の行を出し、メニューの行を「AI を止めて、この会話を閉じる」にする (UC-006 E1)

| 操作 | 画面に起きること |
| --- | --- |
| Space z (または :close) を会話で | 右のウィンドウ「会話を締めくくる」を開く。issue の会話では「締めくくれるのは会話です。issue は、プロジェクトの画面で dd を押して取り下げます」を出す |
| 「この会話を閉じる」で Enter | 会話を閉じ、一覧を開く。お知らせ「会話: <題名> を閉じました。Space b の一覧から開き直せます」 |
| 「AI を止めて、この会話を閉じる」で Enter | AI と動いているスレッドを止めてから閉じる。あとは同じ |
| 「やめて会話に戻る」で Enter、または q | 右のウィンドウを閉じ、会話に戻る。何も変えない |
| 行の Enter (issue・ファイル・コミット・PR) | issue を開く / ファイルを開く / コミットはそのハッシュをコピーする / PR はブラウザの新しいタブで開く |

閉じる操作は確認を挟まない。閉じた会話は開き直せるので、取り返しのつかない操作 (方針 P6) に当たらない。締めくくりの確認のウィンドウが、内容を確かめる場になる。

### 閉じる

`POST /api/conversations/:id/close` を受けた画面のサーバーは、次の順に進める。

1. 会話が `chat` でなければ 409 にする。すでに閉じていれば、未完了の通知の取り下げを試し、保存した `closed_at` を返す
2. ランナーで会話の終了を予約する。止める指定なしで AI が作業中なら 409 にする。止める指定があれば、AI を止めて実行を手放す
3. 会話の予約を取ってからスレッドの一覧を読み、1 件ずつ終了を予約する。動いている AI は止める。スレッドの `closed_at` は変えない (BR-097)
4. ランナーは会話とスレッドの利用枠の戻りを待つタイマーを一時停止する。予約の期限は `features/stock-thread.md`「終了の予約に使う内部の口」に従う
5. 画面のサーバーはトランザクション内で予約を確認する。`closed_at` と、その時点で未取り下げの通知 ID を保存する
6. 配信の `inbox` へ、この会話の id を入れた `changed` を送る。一覧・ツリー・プロジェクトの画面が読み直す (`features/runtime.md`「配信 (`/ws`)」)
7. 取り下げる通知は保存した ID のものに限る (`features/inbox.md`「ほかの端末の通知を消す」)。処理に失敗した場合も閉鎖時刻を返す。再試行では同じ ID を使う

- ランナーにつながらなければ 503 を返し、`closed_at` を書かない
- ストック、送る前の回答、書きかけ、届く前の指示、目次、質問の一覧、決まったことのファイルには触れない (BR-029、BR-097)

### 開き直す (再開)

- 閉じた会話かスレッドに開発者が何かを送ると、ランナーがそれを受け付けたあとに `closed_at` を空にする
- 送るとは、指示の送信、ストックの指示の送信、回答をまとめて送る、届く前の指示を送る、再開の操作である
- ランナーが受け付けなかったとき (503、409 など) は、`closed_at` を書き換えず、閉じたままにする
- 閉じた会話のスレッドに返信したときは、スレッドとあわせて元の会話も開き直す。一覧では、開き直した元の会話の行で扱う
- 開き直したら、配信の `inbox` へ `changed` を送る。会話は、その時点の状態で一覧に戻る
- 開き直しても、利用枠の戻りを待つタイマーは張り直さない。続きを送った指示で動く
- 会話を開く・記録を読む・既読の位置を保存する・締めくくりの確認を開くことでは、開き直さない (BR-096)
- 閉じた会話を開いたときは、お知らせ「閉じた会話です。続きを書いて送ると再開します」を出す
- 閉じた会話に入力欄から指示を送ったときは、お知らせ「送りました。会話を再開し、一覧に戻します」を出す
- 開き直したあとの最初の指示は、保存した `session_id` で会話を再開して届ける (`features/runtime.md`「Agent SDK を包む Port」の再開)。Claude Code が記録を消していて再開できなければ、会話は失敗で止まり、その理由を会話の末尾に出す

開き直す処理は `src/server/modules/conversation/usecase/reopen.ts` に置き、送る操作を持つ API (`features/conversation.md` と `features/stock-thread.md`) が、ランナーが受け付けたあとに呼ぶ。

### 会話とスレッドの一覧

Space b (または :convs) で、主のウィンドウ「会話とスレッドの一覧」を開く。登録しているプロジェクトごとに `GET /api/projects/:id/conversations` を呼び、まとめて 1 つの表にする。

- 列は「題名・状況・プロジェクト・経過」とし、一覧と同じ桁にする
- 開発者が始めた会話 (`chat`) を、閉じたものを含めて、最後の更新が新しい順に並べる。題名は「会話: <題名>」とする
- 会話の行のすぐ下に、そのスレッドを「  スレッド: <題名>」で、スレッドの id (ULID) の順に並べる
- issue の会話のスレッドは、「#<番号> <issue の題名>」の行の下に並べる。この行の位置は、そのスレッドの最後の更新で決める
- 会話の状況は、閉じた会話は「閉じた」とし、それ以外は次の表で `run_state` から決める。会話の状況の語は本書の表が正本である
- スレッドの状況は `features/stock-thread.md`「スレッドの一覧とスレッドの表示」の表で決める

| 会話の `run_state` | 状況の語 |
| --- | --- |
| `idle` | 指示待ち |
| `working` | 作業中 |
| `waiting_answer` / `waiting_permission` | 判断待ち |
| `stopped` | 止まった |
| `failed` | 失敗 |
| `usage_limited` | 利用枠切れ |

- 経過は、最後の更新 (`last_activity_at`) からの時間とする (BR-084)
- 末尾に「閉じた会話は、開くと読めます。続きを書いて送ると再開し、一覧に戻ります。」の説明の行を出す

| 操作 | 画面に起きること |
| --- | --- |
| 会話の行で Enter | その会話を開く。閉じた会話は開き直さない |
| スレッドの行で Enter | 元の会話を開き、右のウィンドウにそのスレッドを出す (`/conversations/<元の会話>?thread=<スレッド>`) |
| issue の行で Enter | その issue を開く |
| 会話の行で dd | y / n の確認「「<題名>」とそのスレッドを削除しますか? 取り消せません」を出す。y で削除し、お知らせ「会話とそのスレッドを削除しました」を出す |
| スレッドの行で dd | y / n の確認「「スレッド: <題名>」を削除しますか? 取り消せません」を出す。y でそのスレッドだけを削除する |
| issue の行で dd | お知らせ「issue は、プロジェクトの画面で dd を押して取り下げます」 |

### 削除

`DELETE /api/conversations/:id` を受けた画面のサーバーは、次の順に進める。

1. 会話が `chat` か `thread` でなければ 409 にする
2. ランナーで会話の終了を先に予約し、そのスレッドも 1 件ずつ予約する。動いている AI を止め、実行を手放す。ランナーにつながらなければ 503 にし、何も消さない
3. 会話とスレッドの、取り下げていない通知を取り下げる。取り下げの push も送る (`features/inbox.md`「ほかの端末の通知を消す」の口を呼ぶ)
4. トランザクションの中で予約が有効であることを確かめる。同じトランザクションで、対象の会話とスレッドの行と、それらを対象とする `notifications` の行を消す
5. イベント・書きかけ・届く前の指示・送る前の回答・ストック・目次・質問は、外部キーの `ON DELETE CASCADE` で同時に消える (DESIGN.md「データスキーマ」)
6. スレッドを消したときは、同じトランザクションで、元の会話のストックのうち、そのスレッドを指す件の `thread_conversation_id` を空にする
7. コミットのあと、会話とスレッドの貼り付けた画像のディレクトリ (`$SUKUNA_HOME/images/<conversation_id>/`。`features/runtime.md`「書くプロセスの分担」) を消す。消せなかったファイルはログに残し、応答は成功にする
8. 配信の `inbox` へ `changed` を送る。元の会話が残る場合は、その会話にもストックとスレッドの `changed` を送る。削除した会話を開いているタブは、次の API 呼び出しで 404 を受ける

- 消さないもの: worktree とそのファイル、リポジトリに置いた決まったことの一覧のファイル (`features/recap.md`)、Claude Code の会話の記録、タイムラインのファイル
- この会話から作った issue も消さない。`issues.created_conversation_id` はそのまま残し、issue の画面が「作った会話は削除されています」と出す (`features/issue.md`)
- 確認は y / n で挟む (方針 P6、DESIGN.md「画面の共通の作り」)。確認で y 以外を押したら、お知らせ「やめました」を出して何もしない

### issue と会話の検索

Space f でコマンド行に `:find ` を出し、語を書いて Enter で検索する。結果は主のウィンドウ「issue と会話を検索」に出す。

- 見出しは「「<語>」を含む issue と会話   n 件」とし、列は「題名・状況・プロジェクト・経過」とする
- 探す対象は、issue の番号・題名・本文と、会話とスレッドの題名とする。閉じた会話、終えたスレッド、下書き・完了・取り下げの issue も含める
- 語は空白で分け、すべてを含むものを返す。英字の大文字と小文字は区別しない
- 語が `#12` か `12` の形なら、番号が 12 の issue も一致にする
- 並びは最後の更新が新しい順で、100 件で打ち切る
- issue の行で Enter を押すと、一覧と同じ規則でその issue を開く (`features/inbox.md`)。会話の行は会話を、スレッドの行は元の会話とそのスレッドを開く

決定: 検索の対象は、issue の番号・題名・本文と、会話とスレッドの題名にする
理由: 「どの issue と会話か」を探す用途は、題名と issue の本文で足りる。会話の本文まで探すと、ツールの出力が一致の大半を占め、結果が読めなくなる
採らなかった案: 会話の発言の本文まで探す (全文の検索の索引が要り、結果の行に一致した文の前後を出す作りも要る)

## API

DESIGN.md「API 一覧」のうち、本機能の 5 本を持つ。エラーの形は DESIGN.md「横断規約 > エラー応答」参照。

### GET /api/conversations/:id/closing-summary

- 200:

```json
{
  "working": false,
  "outputs": {
    "issues": { "ok": true, "items": [{ "id": "01J...", "number": 47, "title": "引き当ての期限を設定値にする", "state": "triage" }] },
    "files": { "ok": true, "items": ["docs/design/features/stock.md"] },
    "commits": { "ok": true, "items": [{ "hash": "3f2a9c1...", "subject": "📝 docs: 期限を設定値にする" }], "more": 0 },
    "prs": { "ok": false, "error": "gh が GitHub にログインしていません" }
  },
  "remaining": {
    "uncommitted": { "ok": true, "items": ["src/order/stock.ts"], "more": 0 },
    "unpushed": { "ok": true, "count": 1, "upstream": true },
    "stock": { "questions": 0, "instructions": 2 },
    "runningThreads": [{ "id": "01J...", "title": "定期処理の負荷は問題ない?", "runState": "working" }]
  },
  "git": true
}
```

- Git と gh から求める項目は `{ "ok": true, ... }` か `{ "ok": false, "error": "<理由>" }` とする
- コミットは新しい順に 50 件、未コミットはパスの順に 20 件まで返し、残りの数を `more` に入れる
- `git` が false なら、Git から求める 4 項目は返さない
- 404 `not_found`: 会話が無い
- 409 `conflict`: 会話が `chat` ではない

### POST /api/conversations/:id/close

```json
{ "stopIfWorking": true }
```

- 200: `{ "closedAt": 1764100000000 }`
- 404 `not_found`: 会話が無い
- 409 `conflict`: 会話が `chat` ではない。AI が作業中で `stopIfWorking` が false (「AI が作業中です。止めて閉じるか、やめてください」)
- 503 `runner_unavailable`: ランナーにつながらない。会話は閉じない

### DELETE /api/conversations/:id

- 200: `{ "deleted": ["01J...会話", "01J...スレッド"] }`
- 404 `not_found`: 会話が無い
- 409 `conflict`: 会話が `chat` でも `thread` でもない (「issue の会話は削除できません。issue を取り下げてください」)
- 503 `runner_unavailable`: ランナーにつながらない。何も消さない

### GET /api/projects/:id/conversations

- 200:

```json
{
  "conversations": [
    {
      "id": "01J...", "title": "予約 API の壁打ち", "runState": "idle", "closedAt": null, "lastActivityAt": 1764100000000,
      "threads": [{ "id": "01J...", "title": "定期処理の負荷は問題ない?", "runState": "idle", "closedAt": 1764100300000, "lastActivityAt": 1764100300000 }]
    }
  ],
  "issueThreads": [
    { "issue": { "id": "01J...", "number": 42, "title": "在庫の引き当て" }, "threads": [{ "id": "01J...", "title": "...", "runState": "idle", "closedAt": null, "lastActivityAt": 1764100000000 }] }
  ]
}
```

- `conversations` は `chat` の会話を閉じたものを含めて、最後の更新が新しい順に返す。`threads` はスレッドの id (ULID) の順とする
- `issueThreads` は、issue の会話から分岐したスレッドを issue ごとにまとめる
- 404 `not_found`: プロジェクトが無いか、登録を解除してある

### GET /api/search?q=<語>

- 200:

```json
{ "results": [
  { "type": "issue", "id": "01J...", "projectId": "01J...", "number": 43, "title": "在庫の引き当て", "state": "implementing", "lastActivityAt": 1764100000000 },
  { "type": "conversation", "id": "01J...", "projectId": "01J...", "kind": "chat", "title": "予約 API の壁打ち", "closedAt": null, "runState": "idle", "lastActivityAt": 1764090000000 },
  { "type": "conversation", "id": "01J...", "projectId": "01J...", "kind": "thread", "parentId": "01J...", "title": "在庫が足りないときの応答は?", "closedAt": 1764090000000, "runState": "idle", "lastActivityAt": 1764090000000 }
], "truncated": false }
```

- 一致は SQL の `LIKE` で、`%` と `_` は文字としてエスケープする
- 400 `invalid_input`: 語が空か、200 文字を超える

## エッジケースの決定

1. **空・最小データ**: 会話が 1 つも無いときは、一覧に「会話はまだありません。Space n で始めます」を出す。締めくくりの確認の何も無い項目は「なし」と出す。検索で一致が無ければ「一致する issue と会話はありません」を出す。語が空なら「検索する語を入れてください」を出し、検索しない
2. **上限・境界値**: コミットは 50 件、未コミットのファイルは 20 件まで出し、残りは「ほか n 件」とする。検索は 100 件で打ち切り、見出しに「(100 件まで)」を添える。検索の語は 200 文字まで。Git と gh の項目は 10 秒で打ち切る。会話とスレッドの一覧は件数で打ち切らない
3. **エラー時に利用者へ見えるもの**: Git と gh の失敗は、その項目の行に「取得できませんでした (<理由>)」を出し、閉じる操作はできるまま残す。閉じる・削除の 503 は、エラーのお知らせに `message` を出し、右のウィンドウと一覧はそのまま残す。消された会話を開いたタブは、主のウィンドウに見つからないことを出す (DESIGN.md「アプリシェル」)
4. **並行操作・二重実行**: 2 つのタブで閉じると、2 回目はいまの `closed_at` を返して成功にする。閉じる前に別のタブから指示が届いて作業中になったら、止める指定の無い閉じる操作は 409 になり、画面は締めくくりの確認を読み直す。閉じたあとに別のタブから送ると、その送信で開き直す。削除の 2 回目は 404 になる
5. **再表示時の整合**: 締めくくりの確認は、開くたびに読む。開いているあいだに、その会話の `state` か `changed` (`stock` / `threads`) が届いたら読み直す。会話とスレッドの一覧と検索の結果は、開くたびと、配信の `inbox` の `changed` を受けたときに読み直す
6. **表示の寿命**: 締めくくりの確認は、閉じるか、やめるか、別の画面へ移ると閉じる。閉じたお知らせと「閉じた会話です」のお知らせは 4 秒で消える。一覧の状況の「閉じた」は、開き直すまで出る
7. **送る前のデータ**: 閉じても、ストック、送る前の回答、書きかけ、届く前の指示はサーバーに残り、開き直すとそのまま使える (方針 P1、BR-097)。削除すると、会話とスレッドの分をまとめて消す
8. **状態の移り変わり**: 会話は、閉じると `closed_at` が入り、開発者が送ってランナーが受け付けると空に戻る。閉じるときに止めた会話は `stopped` のまま残り、送ると再開する。止めたスレッドは閉じずに `stopped` で残る。閉じた会話のスレッドにも返信でき、返信すると元の会話も開き直す
9. **自動で進むこと**: 自動で閉じることはしない。閉じると、利用枠の戻りを待つタイマーが外れ、自動では再開しない。開き直してもタイマーは張り直さない。開き直すのは開発者が送ったときだけである (方針 P2)
10. **端末と画面をまたぐこと**: 閉じたこと・開き直したこと・削除したことはサーバーで共有し、配信でほかの端末の一覧とツリーも変える (方針 P3)。締めくくりの確認の開閉、一覧のカーソル、検索の語と結果は、ブラウザのタブごとに持つ
11. **並びと数え方**: 会話とスレッドの一覧と検索の結果は、最後の更新が新しい順に並べる。スレッドは元の会話の下に、スレッドの id (ULID) の順に並べる。経過は `last_activity_at` から数える (BR-084)。未送信のストックは `stocked` の件を数え、動いているスレッドは `working` / `waiting_answer` / `waiting_permission` の件を数える

- 結合は、本物の SQLite、一時ディレクトリの Git のリポジトリ、Agent SDK の偽物 (`features/runtime.md`) で、画面のサーバーの API とランナーを通して確かめる。gh は偽物にする
- 締めくくりの確認の結合は、コミット 1 件と未コミットのファイル 1 つ、上流のブランチの無い状態を作り、各項目の値を完全一致で確かめる。Git の出力の読み取りは、ドメインの単体テストでも確かめる
- 「閉じた会話を開いただけでは…」は、会話の状態と記録を読む API と、既読の位置の保存を呼んだあと、`closed_at` が閉じたときの値のままで、一覧の API に出ないことを確かめる
- 「AI が作業中の会話を閉じようとすると…」は、止める指定なしで 409 になること、止める指定ありで偽物の停止が呼ばれて閉じることを結合で確かめる。作業中の行とメニューの行の文言は画面の単体テストで確かめる
- 「語を入力して検索すると…選ぶと開く」の「選ぶと開く」は、結果の行の Enter で開く先が種類ごとに決まることを画面の単体テストで確かめる。2 本をあわせてこの行を確かめたことにする
- E2E は、前提データで閉じていない会話を 1 つ用意し、Space z で締めくくりの確認を開いて閉じ、Space b の一覧で選んで開き、続きを送って一覧に戻るまでをキー操作だけで行う。確かめるのは、一覧から外れること、一覧に「閉じた」で並ぶこと、送ったあと一覧に戻ることまでとする

E2E 対象動線: （US-024）会話を閉じる、探す、再開するまでを、Vim と同じ操作感のキーボード操作だけで行える
