# ストックとスレッド

- 種別: 機能設計書
- 対象 UC: UC-004 (docs/design/USECASES.md)

## 何を作るか

回答や成果物の箇所を選んで質問か指示を書き、ストックにためてから送る。質問は 1 件ごとに元の会話を引き継いだスレッドになり、指示はまとめて会話の AI に届く。

**使う人**: 開発者

**流れ**:

1. 会話の回答か、会話から開いたファイルの箇所を、文字・行・矩形のどれかで選び、質問か指示を書く。選ばずに書くと、カーソルの行が引用になる
2. ストックの一覧で見直し、直すか取り消す
3. 全部・質問だけ・指示だけのどれかを選んで送る
4. 質問ごとにスレッドが始まり、AI とやりとりする。終えるときは、AI が出す確定事項の案を直して指示としてストックに入れるか、閉じるだけにする
5. その指示を送る

**主な決まり**:

- 引用 1 つにつき 1 件をストックに入れる。送るまでは直せて、取り消しても戻せる (BR-018)
- ストックはサーバーに置き、どの端末からも見て送れる (BR-022)。会話を閉じても残る (BR-097)
- 指示は、回答のある会話か、ファイルを開いた会話の AI に 1 通で届く。AI が作業中なら、今の作業が終わってから届く (BR-021)
- 質問は送った時点で 1 件ずつスレッドになる。やりとりは元の会話に入らず、ファイルは元の会話と共有する (BR-019、BR-020)
- 選んだ箇所の左に印を付け、ストック・スレッド・送った指示を見分ける。印から中身へ移れる (BR-023、BR-095)
- 終えたスレッドは残り、続きを書いて送ると再開する
- 引用したファイルの箇所が変わると、保存した引用の文と、箇所が古いことを出す

## 入出力と振る舞い

### この機能の前提

- ストックは会話ごとに持つ。送り先は、そのストックを持つ会話である。ファイルの表示では、そのファイルを開いた会話のストックに入る (BR-021、BR-024。ファイルの表示は `features/files.md`)
- 設計の表示 (`features/design-review.md`)、PR の差分 (`features/pr-review.md`)、ターミナルの出力 (`features/worktree-terminal.md`) も、本書の仕組みでストックする。引用の形は、どの種類も本書の「引用の持ち方」が正本である
- スレッドは会話の 1 種 (`conversations.kind = thread`) である。返信・停止・書きかけ・届く前の指示・既読は、会話の API (`features/conversation.md`) をスレッドの id で使う
- 終えたスレッドは、`conversations.closed_at` が入った状態である。続きを書いて送ると、閉じた会話と同じ規則で開き直す (BR-096、`features/conversation-lifecycle.md`)
- 元の会話が閉じていれば、スレッドへの返信で元の会話も開き直す (`features/conversation-lifecycle.md`「開き直す (再開)」)
- 右のウィンドウにスレッドを出しているあいだ、画面は `conversation:<スレッドの id>` を購読する。スレッドの記録と状態の変化はこの購読で受ける (`features/runtime.md`「配信 (`/ws`)」)
- スレッドの中では質問と指示をストックしない。スレッドでは i で直接返信する。スレッドの中にスレッドを作らないためである
- 画面は UI_SKETCH.html の `pc-conv--stock` (ストック) と `pc-conv--thread` (スレッド) を手本にする。部品 (バッファ、右のウィンドウ、メニューの行、入力欄、y / n の確認) は `features/buffer-ui.md` に従う

### 引用の持ち方

引用は `stock_items.quote` に JSON で持ち、形は `src/shared/stock.ts` の Zod のスキーマが正本である。共通の項目は `kind`・`mode`・`text` の 3 つで、位置の持ち方は `kind` ごとに本書が決める。ほかの機能設計書は、本書の形を参照する。

```ts
type Quote = ConversationQuote | FileQuote | DesignDiffQuote | PrDiffQuote | TerminalQuote;
type QuoteMode = "char" | "line" | "block"; // 文字・行・矩形の選択 (v / V / Ctrl+v)
type Pos = { line: number; col: number };
type ConversationQuote = {
  kind: "conversation";
  mode: QuoteMode;
  text: string; // 選んだときの文字列。行は "\n" でつなぐ
  start: { seq: number } & Pos;
  end: { seq: number } & Pos;
};
type FileQuote = {
  kind: "file";
  mode: QuoteMode;
  text: string;
  path: string; // 会話の cwd からの相対パス。区切りは "/"
  start: Pos;
  end: Pos;
};
type DesignDiffQuote = {
  kind: "design_diff";
  mode: QuoteMode;
  text: string;
  path: string; // リポジトリの根からの相対パス
  start: Pos; // 変更後のファイルの行番号
  end: Pos;
};
type PrDiffQuote = {
  kind: "pr_diff";
  mode: QuoteMode;
  text: string;
  path: string; // リポジトリの根からの相対パス
  commit: string; // 引用したときの PR の先頭のコミット (40 桁)
  start: { side: "old" | "new" } & Pos;
  end: { side: "old" | "new" } & Pos;
};
type TerminalQuote = {
  kind: "terminal";
  mode: QuoteMode;
  text: string; // 位置は持たない
};
```

| 項目 | 会話 (`conversation`) | ファイル (`file`) | 設計の差分 (`design_diff`) | PR の差分 (`pr_diff`) | ターミナル (`terminal`) |
| --- | --- | --- | --- | --- | --- |
| 引用する画面 | 会話 | ファイルの表示 (`features/files.md`) | issue の設計の表示 (`features/design-review.md`) | issue の差分の表示 (`features/pr-review.md`) | ターミナルの Normal モード (`features/worktree-terminal.md`) |
| 行 | `seq` のイベントを会話に並べた行のうち、何行目か (0 から)。畳んだ差分は開いた状態で数える | ファイルの行番号 (1 から) | 変更後のファイルの行番号 (1 から)。削除の行は、その位置の変更後の行番号 | `side` の側のファイルの行番号 (1 から)。削除の行は `old`、追加と前後の行は `new` | 持たない |
| 桁 | 行の中の文字の位置 (0 から)。画面のバッファと同じ UTF-16 のコード単位で数える | 同じ | 同じ | 同じ | 持たない |
| `end` | 選んだ範囲の最後の文字の次の位置。行と矩形の選択では、最後の行の行末 | 同じ | 同じ | 同じ | 持たない |
| 古くなるか | 古くならない。会話の記録は書き換えないためである | 「古い引用の判定」で決める | 古くならない。印の付け方は「印」で決める | 古くならない。印の付け方は「印」で決める | 古くならない |
| 指示の文での位置の書き方 | 「この会話の発言から」 | 「<パス> <開始の行>〜<終わりの行> 行目」。1 行なら「<パス> <行> 行目」 | 「設計書の差分 <パス> <開始の行>〜<終わりの行> 行目」 | 「PR の差分 <パス> <側> <開始の行>〜<終わりの行> 行目 (<コミットの先頭 7 文字>)」。側は「変更前」か「変更後」 | 「ターミナルの出力から」 |
| ストックの一覧の位置 | 「会話」 | 「<パス>:<行>」 | 「設計 <パス>:<行>」 | 「PR <パス>:<行>」 | 「ターミナル」 |

- 会話の行とイベントの対応 (どの行が何番の `seq` の何行目か) は `features/conversation.md` の「会話に並べる行」で決まる
- 会話で位置に使える行は、発言・ツールの実行・差分の本文の行だけとする。区切りの行、届く前の指示の行、メニューの行、AI の発言の書きかけの行は、位置に使わない
- 差分で位置に使える行は、追加・削除・前後の行だけとする。ファイルの見出しと「残り n 行」の行は位置に使わない
- 選んだ範囲の最初と最後に近い、位置に使える行を `start` と `end` にする。そうした行が範囲に 1 つも無ければ、ストックに入れない
- 位置の書き方の「<開始の行>〜<終わりの行>」は、1 行の引用では「<行>」にする
- PR の差分で、`start` と `end` の側が違うときは、指示の文の側を「変更前 <開始の行> 行目〜変更後 <終わりの行> 行目」と書く
- PR の差分の引用から、GitHub の行のコメントにできるかは `features/pr-review.md`「指摘を GitHub に投稿する」が決める
- 本文と引用の文の長さは Unicode のコードポイントで数える。たとえば `😀` は 1 文字とする
- 引用の種類を足すときは、本書のこの表に列を足す

### 古い引用の判定

- ファイルの引用だけを判定する。画面のサーバーは一覧を返すとき、ランナーは質問や指示の文を組み立てるときに判定する。ほかの引用は新しいものとして扱う
- いまのファイルから、保存した位置と選び方で文字列を切り出し、保存した `text` と完全に一致すれば新しい。違えば古い
- ファイルが無い・1MB を超える・文字として読めないときも古い (ファイルの読み方は `features/files.md`)
- 箇所を探し直して位置をずらすことはしない。GitHub のレビューの「Outdated」と同じ扱いである

### 印

選んだ箇所の左 (印の桁) に、1 行に 1 つの印を出す。印は、会話・ファイル・設計の差分・PR の差分の表示に付ける。ターミナルの引用は位置を持たないので、印を付けない。

| 印 | 意味 | 付く範囲 | 印の行で Enter |
| --- | --- | --- | --- |
| `!` | ストックの指示 | 引用の全行 | ストックの一覧を開き、その件にカーソルを置く |
| `?` | ストックの質問 | 引用の全行 | 同上 |
| `»` | 終えていないスレッド | 引用の最初の行 | スレッドの表示を開く |
| `✓` | 終えたスレッド | 引用の最初の行 | 同上 |
| `→` | 送った指示 | 引用の最初の行 | 届いていれば、届いた発言へ移る。届く前なら、会話の末尾の届く前の指示の行へ移る |
| `›` | いま書いている引用 | 引用の全行 | 付かない (入力欄を開いている) |

- 1 行に複数あるときは、表の上の印を出す (`›` は最優先)。同じ印の件が複数あれば、id (ULID) の順で最初の件を開く
- 古いファイルの引用には、印を付けない。ストックの一覧には出す
- 設計の差分と PR の差分の引用は、表示中の差分の同じパスと行 (PR では同じ側) の文字列が、保存した `text` の最初の行で始まるときだけ印を付ける。AI が直して行がずれた引用に、別の行の印を出さないためである
- スレッドを終えて入れた指示は、元の質問と同じ引用を持つ。ストックにある間はその行に `!` が出る
- 印はサーバーの一覧から作る。ほかの端末でストックや送信をしても、配信を受けて同じ印になる
- 印の行で Enter を押したとき、行に別の働き (ファイルを開く行など) があっても、印を先にする。ファイルを開くには gf を使う (`features/files.md`)

ストックの一覧の行:

- 1 件を 2〜4 行で出す。1 行目は「<印> <位置> <本文の 1 行目>」とする。位置は「引用の持ち方」の表の「ストックの一覧の位置」で書く
- GitHub に投稿した指示 (`github_comment_url` がある件) は、1 行目の末尾に「GitHub に投稿済み」を付ける。投稿の操作 (Space s g) は `features/pr-review.md` が持つ
- 続けて、引用の先頭 2 行を「    > <文>」で出す。古い引用には「    箇所が古くなっています (保存した引用の文を出しています)」の行を足す
- 最後に「送る (送り先: <会話の題名>)」の見出しと、「全部送る (n 件)」「質問だけ送る (n 件)」「指示だけ送る (n 件)」のメニューの行を出す
- ストックが無いときは「この会話のストックはありません。」と、作り方の説明の行を出す

スレッドの一覧とスレッドの表示:

- 一覧は 1 件を「<» か ✓> <題名>  <状況>」の行と、引用の先頭 2 行で出す。状況は次の表で決める

| スレッドの状態 | 状況の語 |
| --- | --- |
| 終えた (`closed_at` がある) | 終了 |
| `idle` | 指示待ち |
| `working` | 作業中 |
| `waiting_answer` / `waiting_permission` | 判断待ち |
| `stopped` | 止まった |
| `failed` | 失敗 |
| `usage_limited` | 利用枠切れ |

- 終えたスレッドは `run_state` によらず「終了」とする。スレッドの状況の語は本書の表が正本である
- スレッドの表示は、先頭に元の質問の見出しと引用を出し、その下にスレッドの会話を会話と同じ行の形 (`features/conversation.md`) で並べる
- スレッドの最初の開発者の発言 (`origin: "stock"`) は、見出しと引用と同じ中身なので並べない。2 つ目の発言からは「あなた」の発言として並べる
- スレッドの記録には、分岐より前の元の会話の内容を並べない。先頭に「元の会話: <題名> から分岐」の行を出す
- 末尾に、終えていなければ「確定事項をまとめて終える」「閉じるだけ」「このスレッドの AI を止める」(作業中のときだけ) のメニューの行を出す。終えていれば「再開する」のメニューの行を出す。選ぶと入力欄が開き (i と同じ)、続きを書いて送るとスレッドが再開する

ステータス行には、会話を開いているあいだ「ストック 指示 <n> / 質問 <m>」を出す。n と m は送っていない件数である。

### 送る

送る操作は、画面のサーバーがランナーの「ストックを送る」に渡し、ランナーが会話ごとに 1 列に並べて行う。

1. 「API > POST /api/conversations/:id/stock/send」の種類と対象 ID の条件で、状態が `stocked` の件を id (ULID) の順に取る。0 件なら何もせず、件数 0 を返す
2. 指示があれば、届け方を会話の状態で決める。届け方の規則は `features/runtime.md`「画面のサーバーからランナーへの操作」の指示を送る操作と同じである
   - すぐに届けるとき: 全件を「指示の文」の形で 1 通にまとめ、`origin: "stock"` で届ける。同じトランザクションで、各件を `sent` にし、`sent_at` と `sent_seq` (届けた発言の `seq`) を書く
   - 預けるとき: 1 件ずつ、「指示の文」の 1 項目を本文にした届く前の指示 (`queued_instructions`) を作り、`stock_item_id` を書く。同じトランザクションで各件を `sent` にして `sent_at` を書き、`sent_seq` は空のままにする
3. 質問があれば、1 件ずつ「スレッドの始め方」でスレッドを始める。トランザクションは質問 1 件ごとに 1 つで、1 件の失敗はほかの件を止めない (DESIGN.md「トランザクション境界」)
4. 結果を件ごとに返す。失敗した質問は `stocked` のまま残る (UC-004 E2)

- 閉じた会話に指示を送ると、ランナーが受け付けたあとに画面のサーバーが会話を開き直す (BR-096)。受付時と同じ終了時刻が残っている場合だけ開く。質問だけの送信では親を閉じたままにする
- 届く前の指示を届けたときは、同じトランザクションで、`stock_item_id` を持つ行の件に `sent_seq` を書く (`features/conversation.md` の届け方)
- 届く前の指示を取り消したときは、`stock_item_id` を持つ行の件を `stocked` に戻し、印を `!` に戻す。届く前の指示の編集は、ストックの本文を変えない
- issue の会話のストックから指示を送ったときは、届ける前に `flow` の判定を通す。判定の表は `features/conversation.md`「指示を届ける規則」にある (担当でない段階の会話を断る、worktree を作り直す、設計レビューの差し戻し、実装中に戻す)

### 指示の文

すぐに届けるときの 1 通は、次の形にする。

```text
ストックした指示が 2 件あります。順に対応してください。

1. src/order/confirm.ts 5〜7 行目
> await reserve(tx, id);
> await tx.order.update(id, { status: "confirmed" });
期限は設定値から読むようにして

2. この会話の発言から
> 引き当ての期限は 30 分です。
30 分は決済の期限と同じにして
```

- 1 項目は「<番号>. <位置>」の行、引用の全行に「> 」を付けた行、本文の順にする。項目どうしは空行 1 つで区切る
- 古いファイルの引用は、位置の行の末尾に「 (引用した時点の内容。いまのファイルとは違います)」を足す
- 預けるときの 1 件の本文は、番号の無い 1 項目 (位置の行、引用、本文) にする。届けるときは、ほかの届く前の指示と書いた順に並ぶ

### スレッドの始め方

質問を 1 件ずつ分岐する。スレッドの行と送信済みの記録は、最初の指示を受け付けたときに保存する。

1. 送信を始めた時点の元のセッションに、AI の本文、ツールの記録、質問か許可の依頼のいずれかがあれば分岐できる。セッションの初期化だけなら「元の会話に AI の応答がまだ無いため、スレッドを始められません」と返す
2. `AgentPort.fork(元の session_id, { dir: 元の cwd })` で分岐し、新しい `session_id` を受け取る (`features/runtime.md`「Agent SDK を包む Port」の分岐)
3. スレッドの行を作り、ストックの件を `sent` にして `sent_at` と `thread_conversation_id` を書く。最初の指示の記録 (`origin: "stock"`) も同じトランザクションで書く。受付前に実行を開けなければ、すべて取り消す
4. 保存した指示をスレッドの AI に届ける

スレッドの会話の行は、次の値で作る。

| 列 | 値 |
| --- | --- |
| `kind` | `thread` |
| `project_id`、`cwd`、`worktree_id` | 元の会話と同じ |
| `parent_conversation_id` | 元の会話 |
| `issue_id` | 空。issue の状態を動かさないためである (BR-098) |
| `title` | 質問の本文の 1 行目の先頭 40 文字 |

最初の指示は、次の形にする。

```text
次の箇所について質問です。

src/order/confirm.ts 5〜7 行目
> await reserve(tx, id);
定期処理の負荷は問題ない?
```

元の会話の AI が作業中 (`working` / `waiting_answer` / `waiting_permission`) のときは、最初の指示の先頭に次の段落を付ける。

```text
(元の会話の AI は、このスレッドを始めた時点で作業を続けています。記録で中断と出ているツールの呼び出しは、元の会話で動いています。やり直さないでください。ファイルは元の会話と共有しています。)
```

決定: 作業中でも履歴の全体を分岐し、最初の指示に上の注記を付ける
理由: 分岐した側には、実行途中のツールの呼び出しが「中断され結果不明」として写る。注記が無いと、スレッドの AI が同じ操作をやり直し、共有のファイルを二重に変えるおそれがある。全体の分岐は PoC `agent-sdk-thread` で確かめた形である
採らなかった案: 分岐の位置を、最後に完了したメッセージ (`upToMessageId`) で切る (切っても、元の会話が作業中でファイルを変えていることをスレッドの AI が知らないままになり、注記は要る)

- スレッドの AI のツールは制限しない (BR-020)。許可の扱いは元の会話と同じものを渡す
- アプリのツールは、`features/issue.md`「会話の種類ごとに渡すツール」の `thread` の組を渡す
- 分岐は会話の履歴だけを分け、ファイルは元の会話と共有する。スレッドの AI の編集は、元の会話の作業ディレクトリに反映される

### スレッドを終える

確定事項をまとめて終えるときは、次の順に進む。

1. 画面のサーバーは、スレッドに決まった文を `origin: "finish_proposal"` で送る。文は「このスレッドで確定した事項を、元の会話の AI への指示として書いてください。出力は指示の文だけにしてください。確定した事項が無ければ『なし』とだけ書いてください。」とする
2. スレッドの表示には、この文を開発者の発言としては出さず、「確定事項の案を求めました」の区切りの行を出す
3. 番が正常に終わったら、画面はその番の最後の AI の発言を案とする。スレッドの書きかけが空なら、案の文を入れて入力欄「確定事項」を開く。書きかけがあれば、書きかけのまま開く
4. 入力欄の文は、スレッドの書きかけとして保存する (`features/conversation.md` の書きかけの保存)
5. Enter で決定すると、1 つのトランザクションで、指示のストックを足し、スレッドの `closed_at` を書き、スレッドの書きかけを消す。足す指示は、元の質問と同じ引用と、`thread_conversation_id` にこのスレッドを持つ
6. スレッドの実行を手放す (`features/runtime.md` の `release`)

- 最後の開発者の発言が案を求めた文で、その番が正常に終わり、AI の本文があればその案を再利用する。本文が空の番、ツールだけの番、途中で止まった番は案を取り直す
- 閉じるだけのときは、ランナーに終了の予約を取り、作業中の AI を止めて実行を手放す。画面のサーバーが予約のトークンを条件に `closed_at` を書き、ランナーへ完了を知らせる。書きかけは残す
- 終了を保存できなかったときは、予約を待ち始めた時点と予約を解く時点の稼働状態を比べる。状態が変わり、スレッドが開いたままなら、親の購読先に現在の状態を知らせる。
- ランナーは、予約を解除するまで同じ会話の直列処理を保持する。予約中の新しい指示と再開は 409 にする。完了後の返信は通常どおり受け付け、開き直す処理は `features/conversation-lifecycle.md`「開き直す (再開)」に従う
- 終了を保存できるトークンの有効期限は 10 秒とする。サーバーは同じトークンが有効な間だけ終了を保存する。書き込みが競合したときの予約解除は `features/runtime.md`「再開と利用枠の戻り」に従う
- 終了前に予定された届く前の指示の自動配送と、利用枠の自動再開は、終了を保存したあとには動かさない。開発者の送信による再開はそのまま受け付ける
- スレッドを終えても、元の質問の件は `sent` のままで、印は `»` から `✓` に変わる

## API

DESIGN.md「API 一覧」のうち、本機能の 7 本を持つ。エラーの形は DESIGN.md「横断規約 > エラー応答」参照。ストックとスレッドが変わったときは、`conversation:<会話の id>` の購読へ `changed` (`parts` に `stock` か `threads`) を配信する (`features/runtime.md`「配信 (`/ws`)」)。

ストックの 1 件は次の形で返す。

```json
{
  "id": "01J...",
  "conversationId": "01J...",
  "kind": "instruction",
  "text": "期限は設定値から読むようにして",
  "quote": { "kind": "file", "mode": "line", "text": "...", "path": "src/order/confirm.ts", "start": { "line": 5, "col": 0 }, "end": { "line": 7, "col": 52 } },
  "state": "stocked",
  "stale": false,
  "sentAt": null,
  "sentSeq": null,
  "thread": null,
  "githubCommentUrl": null
}
```

- `kind` は `question` / `instruction`、`state` は `stocked` / `sent` / `cancelled` とする
- `thread` は、スレッドを持つ質問と、スレッドから入れた指示で `{ "id", "title", "runState", "closed": true | false }` になる
- `sentSeq` は、届いた発言の `seq` である。預けたまま届いていなければ null
- `githubCommentUrl` は、PR のレビューコメントとして投稿した指示のコメントの URL である。投稿していなければ null (`features/pr-review.md`)

### GET /api/conversations/:id/stock

- 200: `{ "items": [<ストックの 1 件>] }`。`stocked` と `sent` を id (ULID) の順に返す。`cancelled` は返さない
- 古い引用の判定は、このときに行う
- 404 `not_found`: 会話が無い

### POST /api/conversations/:id/stock

```json
{ "kind": "question", "text": "定期処理の負荷は問題ない?", "quote": { "kind": "conversation", "mode": "char", "text": "...", "start": { "seq": 41, "line": 2, "col": 0 }, "end": { "seq": 41, "line": 2, "col": 18 } } }
```

- 201: `{ "item": <ストックの 1 件> }`
- 400 `invalid_input`: 本文が空か 10,000 文字を超える、引用の文が 20,000 文字を超える、引用の形が合わない
- 404 `not_found`: 会話が無い
- 409 `conflict`: 会話がスレッドである (「スレッドでは、i で直接返信します」)

### PATCH /api/stock/:id

```json
{ "text": "期限は設定値から読み、既定は 30 分にして" }
```

```json
{ "state": "stocked" }
```

- 本文を直すか、取り消した件を戻すかのどちらか 1 つを受け取る
- 本文を直せるのは `stocked` の件だけ、戻せるのは `cancelled` の件だけとする
- 200: `{ "item": <ストックの 1 件> }`
- 400 `invalid_input`: 本文が空か長さを超える。両方を同時に送った
- 409 `conflict`: 状態が合わない (「この指示はすでに送っています」)

### DELETE /api/stock/:id

- 200: `{ "item": <ストックの 1 件> }`。`stocked` の件を `cancelled` にする。行は消さない
- 409 `conflict`: `stocked` ではない

### POST /api/conversations/:id/stock/send

指定した種類のストックを送る。取り消した指示を 1 件だけ送り直すときは、同じ口で対象の ID を指定する。

```json
{ "kinds": "all" }
```

```json
{ "kinds": "instructions", "stockIds": ["01J...その件のID"] }
```

- `kinds` は `all` / `questions` / `instructions` とする
- `stockIds` は省略可能な対象 ID の配列とする。指定したときは、会話と `kinds` の条件に加えて ID で絞る。省略すると、選んだ種類の全件を送る
- 200:

```json
{
  "instructions": { "count": 2, "delivery": "delivered" },
  "questions": [
    { "stockId": "01J...", "ok": true, "threadId": "01J..." },
    { "stockId": "01J...", "ok": false, "error": { "code": "fork_failed", "message": "スレッドを始められませんでした。..." } }
  ]
}
```

- `delivery` は `delivered` / `queued` / null (送る指示が無い) とする
- 質問の失敗の `code` は `no_session` (元の会話に応答が無い) / `fork_failed` (分岐に失敗したか、受け付ける前に応答期限が切れた) とする
- 400 `invalid_input`: 種類または対象 ID の形式が合わない
- 404 `not_found`: 会話が無い
- 409 `conflict`: 会話がスレッドである。会話の終了予約中に送ったか、ランナーの直列処理を待つ間に会話が閉じた。issue の担当でない段階の会話に指示を送った (`features/conversation.md`「指示を届ける規則」)
- ランナーの応答を受け取れなくても、受け付け済みの件があれば 200 でその結果を返す。期限内に受け付けなかった質問は失敗として返し、`stocked` のまま残す
- 503 `runner_unavailable`: ランナーの応答を受け取れず、受け付け済みの件が無い。すべての件が `stocked` のまま残る
- 500 `worktree_failed`: 停止中の issue の会話で、worktree の作り直しに失敗した (`features/issue-flow.md`「停止中から戻る」)。どの件も `stocked` のまま残る

ランナーの口は `POST /conversations/:id/stock/send` とする。入力は `kinds`、省略可能な `stockIds`、画面のサーバーが発行する `attempt_id` (UUID)。出力は上の 200 と同じ形とする。

ランナーは、受け付けた結果をストックの状態と同じトランザクションで保存する。応答が途切れたとき、画面のサーバーは SQLite の書き込みロックを取って結果を読み、残りの件の受付を止める。

書き込みが競合したときは、画面のサーバーが最大 20 秒間、ほかの処理を止めずに照合を再試行する。その間に照合できない場合や、別の書き込みエラーが起きた場合は 500 (`internal`) を返す。結果は `settings` の `runner-stock-send:` で始まるキーに 60 秒間残し、後続の送信で期限切れの記録を取り除く。

### GET /api/conversations/:id/threads

- 200: `{ "threads": [{ "id", "title", "stockId", "quote", "runState", "closedAt", "lastActivityAt" }] }`。スレッドの id (ULID) の順に返す
- 404 `not_found`: 会話が無い

### POST /api/threads/:id/finish

```json
{ "action": "propose" }
```

```json
{ "action": "stock", "text": "期限は決済と同じ 30 分とし、設定値から読む" }
```

```json
{ "action": "close" }
```

- `propose`: 確定事項の案を求める。202: `{ "runState": "working" }`。案は、スレッドの記録の AI の発言として届く
- `stock`: 指示をストックに入れて終える。200: `{ "item": <ストックの 1 件>, "thread": { "id", "closedAt" } }`
- `close`: 何も入れずに終える。200: `{ "thread": { "id", "closedAt" } }`
- 400 `invalid_input`: `stock` の本文が空か 10,000 文字を超える
- 404 `not_found`: スレッドが無い
- 409 `conflict`: 終えたスレッドである。`propose` と `stock` で、スレッドの AI が作業中である (「スレッドの AI が作業中です。止めるか、終わってから選んでください」)
- 503 `runner_unavailable`: 案を求められないか、AI の実行を手放せない。終了時刻、ストック、書きかけは変えない

### 終了の予約に使う内部の口

閉じる操作は、次の 2 本を使って、ランナーの直列処理とサーバーの終了保存を連携する。

| メソッド | パス | 入出力 |
| --- | --- | --- |
| POST | `/conversations/:id/release/reserve` | 実行を手放し、`{ "token": "..." }` を返す。閉じるだけのときは作業中の AI を止める。`idle_only: true` のときはスレッドが作業中なら 409 を返す。予約中の新しい指示と再開は 409 にし、ほかの後続操作は予約が解除されるまで進めない |
| POST | `/conversations/:id/release/complete` | `{ "token": "..." }` を受け取り、その予約を解除して `{}` を返す。違うトークンと解除済みのトークンは 409 |

予約は `settings` の `runner-release:<会話の id>` に `{ "token", "expiresAt" }` として持つ。ランナーが作成・解除し、起動時には残った予約を消す。画面のサーバーは、この行のトークンと有効期限を `closed_at` の更新条件に含める。

終了保存のトークンの有効期限は SQLite の時刻から 10 秒後とし、終了を保存するときも SQLite の時刻で比べる。両プロセスの時計の差で有効期間が変わらないためである。予約の解除方法は `features/runtime.md`「再開と利用枠の戻り」に従う。

## エッジケースの決定

1. **空・最小データ**: 本文が空ならストックに入れず、入力欄を開いたまま「内容が空です。書いてからストックしてください」を出す。送る種類の件が 0 件なら、API は件数 0 を返し、画面は「送る質問がありません」「送る指示がありません」「この会話のストックはありません」を出す。選んだ範囲に位置に使える行が無ければ「この行には質問と指示を付けられません」を出す。元の会話に AI の応答が無いときの質問は、`no_session` で失敗する
2. **上限・境界値**: 本文は 1〜10,000 文字、引用の文は 20,000 文字までとする。超える範囲を選んだら「選んだ範囲が長すぎます。20,000 文字以内で選んでください」を出す。1 つの会話のストックの件数と、1 回に送る質問の件数に上限は設けない。スレッドの題名は 40 文字で切る
3. **エラー時に利用者へ見えるもの**: API の失敗は `message` をエラーのお知らせに出し、入力欄の文とストックはそのまま残す。スレッドを始められなかった質問は「質問 1 件はスレッドを始められませんでした。ストックに残しています: <理由>」をエラーのお知らせに出す。送った件を別の端末で直そうとしたときは、409 の文を出し、入力欄の文は残す
4. **並行操作・二重実行**: ランナーは会話ごとに送信を 1 列に並べる。2 回続けて送ると、2 回目は `stocked` の件が無く件数 0 を返す。2 つのタブで同じ件を直したときは、後から届いた本文を残す。送信と取り消しが重なったときは、状態を条件にした更新で先に書いた方だけが通り、もう一方は 409 になる
5. **再表示時の整合**: ストックとスレッドの一覧は、会話かファイルを開いたときと、`changed` (`stock` / `threads`) を受けたときに API で読み直す。つなぎ直したときも読み直す。古い引用の判定は読み直すたびに行うので、ファイルを `:e` で読み直したときも一覧を読み直す
6. **表示の寿命**: `›` は入力欄を閉じると消える。`!` と `?` は送るか取り消すと消える。`»` はスレッドを終えると `✓` に変わり、`✓` と `→` は会話を削除するまで残る。「箇所が古くなっています」は、ファイルが引用と同じ文字列に戻ると消える。送った結果のお知らせは 4 秒で消え、失敗のお知らせは Esc で消すまで残る
7. **送る前のデータ**: ストックはサーバーに置き、送るか取り消すまで残す (方針 P1)。取り消した件は `cancelled` で残し、会話を削除すると消える。会話を閉じても残る (BR-097)。ストックに入れる前の入力欄の文は、そのタブだけに持つ (DESIGN.md「挙動の方針」の P1 の例外)。文があるまま閉じると、確かめずに捨てる。確定事項の案を直している文は、スレッドの書きかけとしてサーバーに置く
8. **状態の移り変わり**: ストックの件は、送ると `sent`、取り消すと `cancelled` に移る。`cancelled` は u で `stocked` に戻る。預けた指示は `sent` で `sent_seq` が空のまま待ち、届くと `sent_seq` が入る。届く前の指示を取り消すと `stocked` に戻る。スレッドは、終えると `closed_at` が入り、続きを送ると空に戻る。スレッドを削除すると、元の質問の `thread_conversation_id` は空になり、印も消える
9. **自動で進むこと**: 送る操作のあと、スレッドの開始と最初の指示は自動で進める。預けた指示は番の終わりに自動で届ける (方針 P2)。確定事項の案の文を入力欄に入れるのは画面で、ストックへ入れるのは開発者の決定だけとする。ランナーが再起動すると、作業中のスレッドは止まった扱いになり、続きを送るまで動かない (`features/runtime.md`)
10. **端末と画面をまたぐこと**: ストック、スレッド、送った状態、印の元になる情報はサーバーで共有する (方針 P1・P3)。右のウィンドウ、カーソル、u で戻す取り消しの履歴、ストックに入れる前の入力欄の文は、ブラウザのタブごとに持つ。u で戻せるのは、そのタブで取り消した件だけである
11. **並びと数え方**: ストックの一覧と指示の文の項目は、作った順 (id の ULID の順) に並べる。引用の元が会話とファイルにまたがるためである。スレッドの一覧もスレッドの id (ULID) の順とする。ステータス行と一覧の件数は `stocked` の件だけを数える。印から印への移動は、表示中のバッファの行の順で、件の最初の行どうしで移る

- 結合は、本物の SQLite と、台本どおりに動く Agent SDK の偽物 (`features/runtime.md`) で、画面のサーバーの API とランナーを通して確かめる。分岐の偽物は、元の会話と別の記録を持つ
- 「スレッドでやりとりを続けても、その内容は元の会話に入らない」は、スレッドに 2 往復したあと、元の会話の記録の件数と `last_seq` が変わらないことを確かめる
- 「終えたスレッドは、元の箇所の印から開けて、続きを書くと再開する」は、印の行で Enter を押すとスレッドの表示が開くことを画面の単体テストで、続きを送ると `closed_at` が空に戻ることを結合で確かめる。2 本をあわせてこの行を確かめたことにする
- 「（US-077）Markdown のプレビューの上で…」は、`features/files.md` の Markdown の表示 (行がソースの行と 1 対 1 のまま装飾する) の上で選んだ範囲が、ソースの行番号の引用になることを確かめる
- 印の優先の順、古い引用の判定、指示の文の組み立ては、ドメインの単体テストで完全一致に確かめる。指示の文は引用の 5 種類をすべて含める
- 選んだ範囲から引用を作る処理は、5 種類の画面の行ごとに画面の単体テストで確かめる。PR の差分では、削除の行が `old`、追加の行が `new` になることを含める
- E2E は、偽物の台本で、指示 1 件と質問 1 件をストックし、Space l で見直し、Space s a で送り、スレッドで確定事項をまとめて終え、入った指示を送るまでをキー操作だけで行う。確かめるのは、印が出ること、スレッドが開くこと、会話に送った発言が出ることまでとし、お知らせの文言は画面の単体テストで確かめる
