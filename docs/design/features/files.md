# ファイル

- 種別: 機能設計書
- 対象 UC: UC-005 (docs/design/USECASES.md)

## 何を作るか

会話が動いているディレクトリのファイルを、アプリの中で探して読み取り専用で読む。AI がその会話のファイルの編集で変えた箇所も差分で読める。

**使う人**: 開発者

**流れ**:

1. 会話からファイルツリーを開くか、中身か名前で検索する
2. ファイルを選ぶと、主のウィンドウに中身が出る。Markdown は見出しや強調を整えた表示で出て、ソースの表示と切り替えられる
3. 回答に書かれたパスからも、同じようにファイルを開ける
4. AI が変えた箇所の一覧を開き、差分で読む
5. 読みながら箇所を選び、質問か指示をストックする

**主な決まり**:

- 対象はその会話が動いているディレクトリ (worktree かプロジェクト) で、その外のファイルは開けない (BR-025)
- 中身の検索は rg と同じ書き方の語を受け付け、ツリーと検索は .gitignore に従う (BR-026)
- 表示は読み取り専用で、直すときは AI に頼む (BR-027)
- 表示も Vim のバッファと同じ操作で動かせる (BR-028)
- Markdown の表示の 1 行は、ファイルの 1 行にそのまま当たる。選んだ箇所の行番号がずれない
- 1MB を超えるか文字として読めないファイルは、中身の代わりに大きさを出す
- 選んだファイルが無くなっていたら、そう出してツリーを読み直す

## 入出力と振る舞い

### この機能の前提

- ファイルの読み取りと検索は画面のサーバーが行う (DESIGN.md「全体構成」)。対象のディレクトリは `conversations.cwd` である
- ファイルツリーは会話ごとに持つ (BR-024)。スレッドは元の会話と同じディレクトリを使うので、スレッドから開いても元の会話のツリーになる
- ファイルの表示で選んだ箇所の質問と指示は、そのファイルを開いた会話のストックに入る。引用の形と印は `features/stock-thread.md` が持つ
- 画面は UI_SKETCH.html の `pc-file` (ツリーとファイル) と `pc-grep` (中身の検索の結果) を手本にする。部品 (バッファ、右のウィンドウ、コマンド行) は `features/buffer-ui.md` に従う
- ファイルの表示を開いているあいだ、画面はその会話と、そのスレッドの `conversation:<id>` を購読する。スレッドはスレッドの一覧 (`GET /api/conversations/:id/threads`) から求める (`features/runtime.md`「配信 (`/ws`)」)
- 画面の URL は `/conversations/:id/file?path=<パス>&line=<行>`、`/conversations/:id/grep?q=<語>`、`/conversations/:id/files?q=<語>`、`/conversations/:id/changes` とする。URL の作りは `features/buffer-ui.md` に従う

### パスの検査

ファイルを読む API と検索は、受け取ったパスを次の順に検査し、どれかに当たれば読まない。

1. 空、NUL を含む、絶対パス、`\` を含むパスは拒む
2. `/` で分けた区切りに `..` があり、正規化すると対象のディレクトリの外に出るパスは拒む
3. 最初の区切りが `.git` のパスは拒む。リモートの URL などの設定が入っているためである
4. 対象のディレクトリと、読むファイルの実体のパス (シンボリックリンクを解決したもの) を求め、実体が対象のディレクトリの中に無ければ拒む

- 拒んだときは 400 `invalid_input` と「会話のディレクトリの外のファイルは開けません」を返す
- ファイルツリーと検索は、シンボリックリンクをたどらない (rg の既定)。外を指すリンクは名前だけが出て、開くと上の 4 で拒む
- 対象のディレクトリが無いとき (worktree を消したあと) は、409 `conflict` と「この会話の作業ディレクトリがありません (<パス>)」を返す

### ファイルツリー

- 一覧は `rg --files --null --hidden -g '!.git'` を対象のディレクトリで実行して得る。.gitignore に従い、隠しファイルは含め、`.git` は含めない。改行を含む名前を分けないよう、パスは NUL 区切りで受け取る。シンボリックリンクの名前は、Git の一覧から補う (DESIGN.md「既知の制約」)
- 20,000 件を超えたら先頭の 20,000 件 (パスの順) だけを返す。ツリーの先頭に「ファイルが多いため 20,000 件まで出しています。:files で名前を検索できます」を出す
- 画面はパスの一覧からフォルダを組み立てる。並びは各階層でフォルダを先、ファイルを後にし、それぞれ名前の順 (大文字と小文字を区別しない) とする
- 右のウィンドウ「ファイル」に出す。1 行目はメニューの行「AI が変えた箇所 (n ファイル)」で、Enter で差分の一覧を開く
- フォルダは最初は閉じておく。ファイルを表示しているときに開くと、そのファイルまでのフォルダを開いてカーソルを置く
- この会話で AI が変えたファイル (差分の一覧に出るもの) には、印の桁に `●` を付ける

| 操作 | 画面に起きること |
| --- | --- |
| Space e | 右のウィンドウ「ファイル」を開く。会話を開いていないときは「会話を開いてから使えます」 |
| フォルダの行で Enter / zo / zc | Enter は開閉を切り替え、zo は開き、zc は閉じる。l と h は Vim のまま、カーソルを左右に動かす |
| ファイルの行で Enter | 主のウィンドウにそのファイルを開く。フォーカスは主のウィンドウに移る |
| :e (ツリーで) | 一覧を読み直す |

- zo と zc の割り当ては、`features/buffer-ui.md` の `files.folder-open` と `files.folder-close` で変えられる

### ファイルの表示

- 主のウィンドウに読み取り専用のバッファで出す。行番号を出し、編集のキーは効かない (BR-027)
- ウィンドウの見出しは「<パス>  <大きさ>  読み取り専用」とする。大きさは 1,024 バイトを 1 KB とし、小数 1 桁で出す
- コードは拡張子から言語を決めて色を付ける。言語の部品は開くときに読み込み、決まらない拡張子は色を付けない
- 改行が CRLF のファイルは LF として出す。先頭の BOM は出さない。行の数え方は変わらない
- 空のファイルは「(空のファイル)」の説明の行だけを出す
- `-` で 1 つ前の画面 (検索の結果や会話) へ戻る。戻った画面のカーソルは、開く前の位置に戻る (`features/buffer-ui.md`「位置の記憶」)

Markdown (拡張子 `.md` と `.markdown`) は、次の 2 つの表示を持つ。開いたときは整えた表示にする。

| 表示 | 中身 |
| --- | --- |
| 整えた表示 (プレビュー) | ソースの行をそのまま出し、装飾で整える。見出しは大きく太く、強調は太字や斜体、コードは等幅に地の色を付ける。`#`・`**`・`` ` `` などの記号は、カーソルの行でだけ出し、ほかの行では隠す。リンクは文字だけを強調色で出す。画像は「[画像: <代わりの文>]」と出し、読み込まない。表と HTML は等幅の文字のまま出す |
| ソースの表示 | 記号を含めて、コードと同じに出す |

- Space v で 2 つの表示を切り替える。切り替えても、カーソルの行と、ストックの印の行は変わらない
- 整えた表示でも、選んだ範囲の位置はソースの行と桁で数える。引用の位置がずれないためである

決定: Markdown のプレビューは、ソースの行を保ったまま装飾で整える表示にする
理由: 表示の 1 行がファイルの 1 行に当たるので、選んだ箇所をそのまま行番号の引用にできる。HTML に変えると、選んだ範囲からソースの行を逆に求める必要があり、表やリストで位置がずれる
採らなかった案: HTML に変えて描くプレビュー (表や画像を整った形で出せるが、引用の位置が保てない)

### 回答の中のパスから開く

- 会話のバッファで gf を押すと、カーソルの下の語をパスとして開く。語は空白で区切り、前後の `` ` ``・`'`・`"`・`(`・`)`・`[`・`]`・`<`・`>` と、末尾の `.`・`,`・`;`・`:` を除く
- `<パス>:<行>` と `<パス>:<行>:<桁>` の形なら、開いてその行へ移る
- 対象のディレクトリの中の絶対パスは、相対パスに直して開く。外の絶対パスは開かず「会話のディレクトリの外のファイルは開けません」を出す
- ツールの実行の行 (「● Read(<パス>)」「● Update(<パス>)」など) は、Enter でもそのパスを開く (`features/conversation.md`「開発者の操作と画面に起きること」)
- パスのファイルが無ければ「ファイルがありません: <パス>」をお知らせに出し、画面は移らない

### 検索

| 操作 | 画面に起きること |
| --- | --- |
| Space / | コマンド行に `:rg ` を出す。続けて語を書き、Enter で中身を検索する |
| :rg <語> | 主のウィンドウ「ファイルの中身を検索」に、見出し「rg "<語>"   n 件」と、一致した行を「<パス>:<行>:  <行の文>」で並べる |
| :files <語> | 主のウィンドウ「ファイルの名前を検索」に、見出し「files "<語>"   n 件」と、一致したパスを並べる |
| 結果の行で Enter | そのファイルを開き、一致した行へ移る。中身の検索では一致した桁にカーソルを置く |

- `:rg` の語は、`:rg ` の後ろの文字列を空白を含めてそのまま 1 つのパターンとして rg に渡す。オプションは受け付けない。大文字と小文字を区別しないときは、パターンの先頭に `(?i)` を書く (rg の正規表現の書き方)
- rg は、対象のディレクトリで、引数の配列として実行する (シェルを通さない)。一覧と中身の検索では、子プロセスの環境から `RIPGREP_CONFIG_PATH` だけを除き、ユーザーの設定ファイルを読ませない。中身の検索へ渡すのは `--json --hidden -g '!.git' --max-columns 500 -e <パターン>` だけとする
- `:files` の語は、空白で分けた語のすべてを含むパスを返す。大文字と小文字は区別しない。一覧はファイルツリーと同じものを使う
- 会話を開いていないときは「会話を開いてから検索してください」を出し、検索しない
- 語が空なら「検索する語を入れてください」を出す

決定: 中身の検索は、パターンだけを受け付け、rg のオプションは受け付けない
理由: rg には、外のコマンドを実行するオプション (`--pre`) や、探す場所を変える引数がある。オプションを通すと、対象のディレクトリの外を読ませる口になる。大文字と小文字の区別はパターンの中の `(?i)` で足りる
採らなかった案: `-i`・`-w`・`-g`・`-t` などを許す一覧を作って通す (許す範囲の検査を保ち続ける手間がかかり、検索の機能としての差は小さい)

### AI が変えた箇所

- この会話の記録の `diff` イベント (`features/runtime.md`「会話の記録の種類」) から作る。スレッドで AI が変えた箇所は、そのスレッドの記録に残り、ここには含めない
- 記録の相対パスと、作業ディレクトリ内を指す絶対パスは、同じ正規化済み相対パスへそろえる。変更印、集計の単位、返すパスにはこの表記を使う
- 記録のパスも実体が作業ディレクトリ内にあることを検査し、外や `.git` を指すものは除く。削除済みのファイルは、残っている最も近い親の実体を検査し、差分は保持する
- 主のウィンドウ「AI が変えた箇所」に、ファイルごとに見出し「<パス>  追加 n 行、削除 m 行」を出し、その下に編集ごとの差分を並べる
- 差分は、会話の中と同じ見せ方 (行番号付きで追加と削除を色分け) にする (BR-075)。ここでは畳まない
- 編集ごとに「<時刻> <編集 / 作成 / 書き換え>」の行を置く。この行で Enter を押すと、会話のその記録の行へ移る
- 差分の行で Enter を押すと、ファイルを開いてその行へ移る。追加と前後の行は新しい行番号、削除の行はその位置の新しい行番号を使う
- 記録が途中で切られた差分 (`truncated`) には「(差分が大きいため、一部を省いています)」の行を出す
- 先頭に「コマンド (Bash など) で変えたファイルは含みません」の説明の行を出す
- この画面では質問と指示をストックしない。Space q / Space c を押すと「差分には、会話かファイルの表示で質問と指示を付けてください」を出す
- 開く入口は、ファイルツリーの 1 行目のメニューの行と、コマンド `:changes` とする

### 開いているファイルが変わったとき

- 開いているファイルについて、この会話かスレッドの `diff` イベントが購読で届いたら、ウィンドウの見出しに「AI がこのファイルを変えました。:e で読み直します」を出す
- 中身は自動で読み直さない。選んでいる途中の範囲や、ストックを書いている箇所が動かないためである
- :e で読み直すと、同じ行番号にカーソルを置き、ストックの一覧も読み直す (`features/stock-thread.md`)
- ファイルを作った `diff` イベント (`change: "create"`) が届いたとき、ファイルツリーを開いていれば、1 秒待ってから一覧を読み直す。続けて届いた分は 1 回にまとめる

## API

DESIGN.md「API 一覧」のうち、本機能の 4 本を持つ。エラーの形は DESIGN.md「横断規約 > エラー応答」参照。4 本とも、会話が無ければ 404 `not_found`、作業ディレクトリが無ければ 409 `conflict` を返す。

### GET /api/conversations/:id/files

- 200:

```json
{ "files": ["docs/DESIGN.md", "src/order/confirm.ts"], "truncated": false, "changed": ["src/order/confirm.ts"] }
```

- `files` はパスの順に並べる。`changed` は、この会話で AI が変えたファイルのうち、いまもあるもの

### GET /api/conversations/:id/files/content?path=<パス>

- 200 (文字のファイル):

```json
{ "path": "src/order/confirm.ts", "kind": "text", "size": 1834, "content": "import { db } from \"../db\";\n..." }
```

- 200 (表示しないファイル): `{ "path", "kind": "too_large" | "binary", "size" }`。`content` は付けない
- `kind` の決め方: 大きさが 1,048,576 バイトを超えれば `too_large`。超えなければ読み、先頭 8,000 バイトに NUL があるか、UTF-8 として読めなければ `binary`。それ以外は `text`
- `content` は、BOM を除き、CRLF を LF にしたものとする
- 400 `invalid_input`: パスの検査に落ちた。ディレクトリを指した (「ディレクトリは開けません。ファイルツリーで開いてください」)
- 404 `not_found`: ファイルが無い (「ファイルがありません: <パス>」)

### GET /api/conversations/:id/search?mode=<content|name>&q=<語>

- 200 (`mode=content`):

```json
{ "mode": "content", "query": "reserve", "matches": [{ "path": "src/order/confirm.ts", "line": 5, "col": 8, "text": "  await reserve(tx, id);" }], "truncated": false, "timedOut": false }
```

- 200 (`mode=name`): `{ "mode": "name", "query": "confirm", "matches": [{ "path": "src/order/confirm.ts" }], "truncated": false }`
- `matches` はパスの順、同じファイルの中は行の順に並べる。`col` は行の中の最初の一致の位置 (0 から)
- `col` は、画面のバッファと同じ UTF-16 コード単位で数える。rg が返すバイトの位置を、その行の文字の位置に直して返す (DESIGN.md「既知の制約」)
- 中身の検索は 1,000 件、名前の検索は 200 件で打ち切り、`truncated` を true にする
- 中身の検索が 10 秒で終わらなければ rg を止め、それまでの結果と `timedOut: true` を返す
- 400 `invalid_input`: 語が空、`mode` が違う、パターンが正規表現として読めない (rg のエラーの 1 行目を `message` に入れる)
- 500 `internal`: rg を実行できない (「rg が見つかりません。Mac に ripgrep を入れてください」)

### GET /api/conversations/:id/changes

- 200:

```json
{
  "files": [
    {
      "path": "src/order/confirm.ts",
      "added": 3,
      "removed": 1,
      "changes": [{ "seq": 57, "createdAt": 1764100000000, "change": "edit", "hunks": [{ "oldStart": 4, "oldLines": 2, "newStart": 4, "newLines": 4, "lines": [" ...", "+..."] }], "truncated": false }]
    }
  ]
}
```

- `files` は、そのファイルを最初に変えた `seq` の順に並べる。`changes` は `seq` の順とする
- `added` と `removed` は、そのファイルの全部の差分の `+` と `-` の行の数の合計である
- `change` が `create` の記録は、`content` の全行を追加の行として返す

## エッジケースの決定

1. **空・最小データ**: ファイルが 1 つも無いディレクトリでは、ツリーに「ファイルはありません」を出す。空のファイルは「(空のファイル)」を出す。一致が無い検索は「一致する行はありません」「一致するファイルはありません」を出す。AI が何も変えていない会話の差分の一覧は「この会話で AI が変えたファイルはありません」を出す
2. **上限・境界値**: ちょうど 1,048,576 バイトのファイルは表示し、1 バイトでも超えれば表示しない。ツリーは 20,000 件、中身の検索は 1,000 件、名前の検索は 200 件で打ち切る。中身の検索の結果の 1 行は 500 文字で切る (rg の `--max-columns`)。中身の検索は 10 秒で止める
3. **エラー時に利用者へ見えるもの**: ファイルが無ければ、主のウィンドウに「ファイルがありません: <パス>」を出し、ツリーを開いていれば読み直す (UC-005 E1)。大きいファイルは、主のウィンドウに「表示できません (大きさ 3.2 MB、上限 1 MB)」を出す。読めないファイルは「文字として読めないため表示できません (大きさ 120.0 KB)」を出す (UC-005 E2)。外のパスと作業ディレクトリが無いときは、API の `message` を主のウィンドウに出す
4. **並行操作・二重実行**: 読み取りだけで状態を変えない。続けて検索したら、前の要求を取り消し、最後の検索の結果だけを出す
5. **再表示時の整合**: ファイルの中身は、開くたびと :e のたびに API で読む。画面の履歴で戻ったときも読み直し、カーソルは同じ行番号に置く。ツリーは開くたびに読み直す
6. **表示の寿命**: 「AI がこのファイルを変えました」は、:e で読み直すか、別のファイルか画面へ移ると消える。ツリーの `●` は、この会話で AI が変えたファイルに付き続ける。検索の結果は、そのタブの画面の履歴に残る
7. **送る前のデータ**: 該当なし (読むだけの機能で、送るものを持たない。ストックは `features/stock-thread.md`)
8. **状態の移り変わり**: Markdown の表示は、開くたびに整えた表示から始まり、Space v で切り替わる。ファイルは、開くたびに text・too_large・binary・無いのどれかに決まる
9. **自動で進むこと**: ファイルを作った差分が届くと、開いているツリーを読み直す。ファイルの中身は自動で読み直さない
10. **端末と画面をまたぐこと**: 共有するものは無い (方針 P3)。フォルダの開閉、カーソル、Markdown の表示の切り替え、検索の語と結果は、ブラウザのタブごとに持つ
11. **並びと数え方**: ツリーはフォルダを先にして名前の順、検索の結果はパスと行の順、差分の一覧は最初に変えた順とする。大きさは 1,024 バイトを 1 KB、1,048,576 バイトを 1 MB として小数 1 桁で出す。行番号は 1 から数える

## テスト方針

| 受け入れ基準 (docs/design/USECASES.md) | レベル |
| --- | --- |
| （US-066）会話のファイルツリーを開くと、その会話が動いているディレクトリのファイルとフォルダが表示される | 結合 |
| （US-066）ファイルツリーでファイルを選ぶと、その内容が読み取り専用で表示される | 単体 |
| （US-049）回答に書かれたファイルのパスを選ぶと、そのファイルが開く | 単体 |
| （US-049）差分の表示を選ぶと、会話の中で AI が変えた箇所が差分で表示される | 結合 |
| （US-077）Markdown のファイルを開くと、プレビューで表示され、ソースの表示と切り替えられる | 単体 |
| （US-067）語を入力して中身を検索すると、一致した行がファイル名と行番号とともに並ぶ | 結合 |
| （US-067）検索結果の 1 行を選ぶと、そのファイルが開き、一致した行へ移動する | 単体 |
| （US-066）選んだファイルが無くなっていると、無いことが表示され、ファイルツリーが更新される | 単体 |
| （US-049）1MB を超えるか文字として読めないファイルを選ぶと、表示できないこととファイルの大きさが表示される | 結合 |

- 結合は、一時ディレクトリに作った Git のリポジトリ (.gitignore を含む) を会話の `cwd` にして、画面のサーバーの API を通して確かめる
- パスの検査は、ドメインの単体テストで、`..` で外に出るパス、絶対パス、`.git`、外を指すシンボリックリンク、中を指すシンボリックリンクを確かめる。結合でも、外を指すリンクを開くと 400 になることを 1 本確かめる
- 1MB の境界は、1,048,576 バイトと 1,048,577 バイトのファイルで確かめる
- 中身の検索は、.gitignore に書いたファイルが結果に出ないこと、`--pre` などのオプションを書いた語がパターンとして扱われることを確かめる
- E2E は、Space e でツリーを開き、j / k と Enter でファイルを開く流れと、Space / で検索して結果の行から開く流れを 1 本の中で行う。確かめるのは、ファイルの中身が出ることと、一致した行にカーソルがあることまでとする

E2E 対象動線: （US-024）ファイルを探して開き、読むまでを、Vim と同じ操作感のキーボード操作だけで行える
