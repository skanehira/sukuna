# 会話の状況を思い出す

- 種別: 機能設計書
- 対象 UC: UC-003 (docs/design/USECASES.md)

## 何を作るか

別の作業から会話に戻った開発者が、どこから読むか、次に何を答えるか、前に何を決めたかを、会話を読み返さずにつかめるようにする機能。

**使う人**: 開発者 (PC のブラウザで、キーボードだけで操作する)

**流れ**:

1. 会話を開くと、未読の回答の先頭が「ここから未読」の区切りと一緒に出る。未読が無ければ、自分の最後の発言が出る
2. 未読があれば、右のウィンドウに直近 (AI の質問、自分の最後の発言、書きかけ、ストックとスレッドの件数) が出る
3. 質問を選ぶと、本文のその質問へ移る。前回読んでいた位置へも戻れる
4. 目次を開いて章を選ぶか、決まったことの一覧を開いて 1 件を選ぶと、本文のその場所へ移る
5. 目次と一覧で語を検索したり、章の名前・区切り・決まったことを直したりする

**主な決まり**:

- 目次・決まったこと・文章の質問は、AI の番が終わるたびに、会話とは別の小さいモデルが更新する。会話の AI の文脈には入れない (BR-012)
- 質問の一覧は、AI の文を要約せずにそのまま並べる (BR-013)
- 決まったことの一覧は、プロジェクトのリポジトリの中の、会話ごとの Markdown のファイルに置く。アプリで直すと、そのファイルが書き換わる (BR-015)
- 会話の AI は、決まったことの一覧と目次を読める (BR-016)
- 「ここから未読」の区切りは、読んでいるあいだと再読み込みのあとは残し、会話の画面を離れると消える (BR-078)
- 既読の位置と前回読んでいた位置は、どの端末でも同じにする。カーソルと開いている表示は、ブラウザのタブごとに持つ (BR-087)
- 目次などの更新に失敗したら、最後に作れた目次と失敗したことを出し、作り直しを選べる。次の番の終わりにも自動でやり直す

## 入出力と振る舞い

### この機能の前提

- 会話の本文の表示、イベントの読み込み、表示の追従は `features/conversation.md` が持つ。本書は、開いたときのカーソルの位置と、右のウィンドウの直近・目次・決まったことを持つ
- 右のウィンドウ、表示の履歴 (Ctrl+h で 1 つ前の表示へ戻る)、ジャンプの履歴 (Ctrl+o) の作りは `features/buffer-ui.md` が正本である
- 質問の一覧 (`questions`) は、選択式の質問と文章の質問の両方を持つ。選択式はランナーが質問を受けたときに追加し、回答を送ると回答済みにする (`features/conversation.md`)。文章の質問は、本書の更新が追加し、回答済みにする
- 一覧の「判断待ち」の判定 (BR-073) と未読の印 (BR-004) は、本書が持つ質問の一覧と既読の位置を `features/inbox.md` が読んで決める
- ストックとスレッドの件数は `features/stock-thread.md` から読む
- 一覧は、番の終わりのセクションの判定と通知を、その番が `conversations.recap_seq` に反映されるか `recap_failed_at` が立つまで待つ。待たないと、指示待ちの通知のあとに質問が見つかり、判断待ちの通知がもう 1 回出る (BR-003)
- 待つあいだの一覧の表示は `features/inbox.md`「一覧のセクション分け」の番の終わりの待ちが決める。待ちに時間の上限は置かない
- 本書は、待ちが終わる合図となる 2 つの列と、待ちが残り続けないための積み直し (「番ごとの更新」) を持つ

### 会話を開いたときの位置

画面は UI_SKETCH.html の `pc-conv--recent` を手本にする。

| 開いたときの条件 | カーソルを置く行 | 右のウィンドウ |
| --- | --- | --- |
| 未読の回答がある | 「ここから未読」の区切りの次の行。区切りとその次の行をウィンドウの上部に出す | 右の表示を維持する条件に当たらなければ、直近を自動で開く (BR-102) |
| 未読の回答が無く、開発者の発言がある | 開発者の最後の発言の最初の行 | 開かない |
| 開発者の発言も無い | 末尾の行 | 開かない |
| 開いた時点で `run_state` が `working` | 末尾の行 (表示を追う状態) | 未読があり、右の表示を維持する条件に当たらなければ、直近を開く |

- 未読の回答は、`seq` が `conversations.last_read_seq` より大きいイベントのうち、開発者の発言以外のものとする
- 区切りの位置は、開いたときの `last_read_seq` で決め、タブの中 (sessionStorage) に会話ごとに覚える。再読み込みしても同じ位置に出す
- 会話の画面を離れると、そのタブで覚えた区切りを消す。次に開いたときは、そのときの `last_read_seq` で区切りを置き直す
- 開いたときの `conversations.last_position` を「前回読んでいた位置」としてタブの中に覚え、ジャンプの履歴の 1 つ前に積む。開いた直後の Ctrl+o で、その位置へ移る (UC-003 F)
- 右のウィンドウの直近は、別の会話へ移ると閉じる。移った先に未読の回答があれば、表の条件で直近を開く
- 右に「会話を始める・切り替える」を表示中は、その表示を保つ。URL がスレッドを指定している場合も、そのスレッドを保つ。会話切り替えとスレッドの維持方法は `features/buffer-ui.md`「ウィンドウの構成と移動」に従う

### 既読と読んでいた位置の保存

- 会話を開いてイベントを読み終えたら、`POST /api/conversations/:id/read` で既読の位置を最後の `seq` まで進める
- 会話を主のウィンドウに出していて、タブが見えているあいだは、届いたイベントを読んだものとし、1 秒ごとにまとめて既読の位置を進める。タブが隠れているあいだは進めない
- 既読の位置は増やす方向にだけ動かす。サーバーは、届いた値と保存済みの値の大きい方を残す
- 読んでいた位置は、カーソルのある行のイベントの `seq` とする。カーソルが 2 秒止まったときと、会話から離れるとき (別の画面へ移る、タブを閉じる) に保存する
- タブを閉じるときの保存は、ページを離れても届く送り方 (`fetch` の `keepalive`) で送る

### 直近

右のウィンドウに次の順で出す。行はどれも Enter で開くか移動する。

| 見出し | 行 | Enter |
| --- | --- | --- |
| 判断すること n | 未回答の質問の文をそのまま 1 行ずつ。許可の確認を待っていれば「許可の確認: <ツール名>(<対象>)」も | 本文のその質問の行へ移る |
| 自分の最後の発言 | 開発者の最後の発言の本文 | 本文のその発言へ移る |
| 書きかけ | 「入力の書きかけ (i で続きを書く)」(あるときだけ)、「ストック n 件」、「スレッド n 件 (動いているもの m 件)」、「届く前の指示 n 件」(あるときだけ) | ストックとスレッドは、その一覧を右のウィンドウに開く |
| 遡る | 「未読の先頭へ」(区切りがあるときだけ)、「前回読んでいた位置へ」、「目次」、「決まったこと」 | 移るか、その表示を開く |

- 未読が無いときは、開発者が Space i で開く (BR-102)
- 質問の行には、質問の文全体を出す。右のウィンドウの幅を超える文は折り返す

### 目次

画面は UI_SKETCH.html の `pc-conv--toc` を手本にする。Space m で右のウィンドウに開く。

- 章ごとに「<番号> <章の名前>」の行を出し、その下に章の範囲で決まった項目 (種類が決定で、変わった先が無いもの) を「決定: <内容>」の行で並べる
- 主のウィンドウのカーソルがある章の行に「いまここ」を付ける
- 章の範囲は、その章の `start_seq` から、次の章の `start_seq` の 1 つ前までとする
- 章の行か決定の行で Enter を押すと、本文のその章の先頭へ移る。移る前の位置は Ctrl+o で戻れる
- 最後の行に「章の名前は AI が付けます。/ で検索できます。」を出す
- 更新に失敗しているときは、最後に作れた目次の下に「目次を更新できませんでした (<時刻>)」と、メニューの行「目次を作り直す」を出す
- 更新の途中は、最後の行に「最後の往復を反映しています」を出す

### 決まったことの一覧

画面は UI_SKETCH.html の `pc-conv--decisions` を手本にする。Space d で右のウィンドウに開く。

- 記録の順に「決定: <内容>」「採らなかった案: <内容> — <理由>」「保留: <内容>」の行を出す。保留の行は判断待ちの色にする
- 後で変わった項目は、行の末尾に「→ 変わった先: <変わった先の内容>」を付ける
- 行で Enter を押すと、本文の根拠の発言へ移る。根拠の無い項目 (ファイルを手で書き足したもの) では、お知らせに「根拠の発言がありません」と出す
- 最後の行に「リポジトリの <ファイルのパス> に保存しています。」を出す

### 決まったことのファイル

決定: 会話ごとに 1 つのファイルを、プロジェクトのディレクトリの `docs/decisions/<会話の ID>.md` に置く。

理由: 会話が worktree で動いても、worktree を消すとファイルも消える場所には置かない。自動フローの worktree に置くと、実装の PR にファイルが混ざる。会話ごとに分けると、並行する会話の書き込みがぶつからない。

採らなかった案: 全会話で 1 つの `docs/DESIGN_NOTES.md` に書く (並行する会話と、worktree の枝どうしで、同じファイルの書き込みがぶつかる)。会話の作業ディレクトリに置く (worktree を消すと失われ、自動フローの PR に混ざる)。

内容と理由は JSON 文字列で引用する。本文に区切り記号や改行があっても、項目のメタデータと区別して読み戻せる。

- 先頭行に版の印 `<!-- sukuna-decisions:v2 -->`、またはランナーが書く `<!-- sukuna-decisions:v3 recap=<最後の seq>:<UUID> -->` を置く
- v3 の最後の seq は先頭の 0 を含まない正の安全な整数とする。UUID は小文字の UUID v4 とする
- 適用済みの番を示すのは、v3 の形に合う先頭行だけとする。本文中のコメントやコード例は手書きの行として保つ

```markdown
<!-- sukuna-decisions:v2 -->
# 決まったこと: 予約 API の壁打ち

- 種別: 決定台帳
- 会話: 01JDX4Q8ZK3W7M2N5P6R9T0V1A

- [決定] D1: "機能は検索・作成・取り消しの 3 つにする" <!-- seq=4 -->
- [決定] D2: "取り消しは開始の 24 時間前までにする" → D5 <!-- seq=9 -->
- [棄却] D3: "認証を新しく作る" — "既存のセッションを使うため" <!-- seq=5 -->
- [保留] D4: "引き当ての期限を設定で変えられるか" <!-- seq=15 -->
- [決定] D5: "取り消しは開始の 12 時間前までにする" <!-- seq=40 -->
```

- 1 項目を 1 物理行で書く。行の形は `- [<種類>] D<番号>: <内容の JSON 文字列>[ — <理由の JSON 文字列>][ → D<番号>][ <!-- seq=<根拠の seq> -->]` とする
- 内容と理由の改行・引用符は JSON のエスケープで保存する。理由が null のときだけ理由の部分を省く。空文字の理由は `""` とする
- 種類、番号、変わった先、根拠は引用した文字列の外に置く。内容と理由では ` — `、`→ D<番号>`、`<!-- seq=n -->`、改行も使える。文字数と空文字の許否は API の検査に従う
- 種類は `決定` / `棄却` / `保留` の 3 つで、画面では「決定」「採らなかった案」「保留」と出す
- `→ D<番号>` は、その項目が後で変わり、変わった先がその番号の項目であることを示す
- 番号の桁数に上限は設けず、ファイルの中の最大の番号に 1 を足して十進数で振る
- 内容と理由は Unicode コードポイントでそれぞれ 200 文字まで、根拠の seq は 0 以上の安全な整数とする。形や上限に合わない行は読み飛ばし、書き込むときは原文を残す
- ファイルは、最初の項目を足すときに作る。題名は、そのときの会話の題名とする
- ファイルのコミットはアプリでは行わない。開発者か AI がコミットする

版の印が無いファイルは、`- [<種類>] D<番号>: <内容>[ — <理由>][ → D<番号>][ <!-- seq=<根拠の seq> -->]` の規則で読む。この形式の引用符は内容や理由の文字として扱う。アプリで保存するときは、読めた項目の意味と手書きの行を保ち、先頭に版の印を付けた形式へ移す。

移行後に項目と同じ形になる手書き行は、元の行を変えずに由来の情報を添えて、未管理のまま残す。由来の情報と同じ形の手書き行も保護する。保護が要るファイルでは、版の印の次の行に `<!-- sukuna-decisions:unmanaged:v1 <JSON 配列> -->` を置く。配列の各要素は、対応する印の `token` と元の行の `text` を持つ。JSON の中の `<` と `>` は Unicode のエスケープで書く。

保護する行の前後に `<!-- sukuna-decisions:unmanaged:u1:begin -->` と `<!-- sukuna-decisions:unmanaged:u1:end -->` を置く。`u1` は既存の手書きの印と重ならない番号を選ぶ。この印の間の文は、外部エディターで直したり、印ごと別の位置へ移したりしても未管理のままとする。行だけを移した場合は、由来の情報にある元の文と照合する。保存のたびに印を組み直し、同じ文の管理項目があっても手書き行を残す。

ファイルへの書き込みは、ランナーと画面のサーバーの両方が使う共通のストアで行う。対象ファイルごとにプロセス間の排他を取り、読み出しから一時ファイルの置換が終わるまで保持する。異なる会話のファイルは別の排他にする。

排他には、同じユーザーの一時ディレクトリに置く SQLite の `BEGIN IMMEDIATE` を使う。プロジェクトの実体のパスと会話のファイルのパスから、排他用のファイルを決める。接続を閉じるか、プロセスが強制終了すると OS が排他を解放する。5 秒待っても取れなければ 409 `conflict` とする。

排他を待った後で `baseHash` と違えば、アプリでの修正は 409 にする。`baseHash` のない更新は、新しく読んだ内容に当てる。書く直前にも SHA-256 を比べ、違えば読み直して当て直す。3 回続けて違えば失敗とする。排他に参加しない外部エディターは、この比較と置換の間にも書けるため、その区間の変更の保持は保証しない。

### 番ごとの更新

- ランナーは、AI の番が終わるたびに (正常に終わったか止まったかを問わない)、その会話の更新を 1 件の仕事として積む。仕事は会話ごとに 1 つずつ順に行う
- 仕事を積むとき (番の終わり、作り直し、起動時の積み直し)、`recap_failed_at` を空にする。前の番の失敗が残っていると、一覧が待たずに判定へ進むためである
- 番の範囲は、`conversations.recap_seq` (反映済みの最後の `seq`) の次の `seq` から、その後の最初の `turn_end` の `seq` までとする
- この範囲には、再起動で止まって `turn_end` を持たない番の記録も、次の番の記録と一緒に入る
- 1 回の更新は、この範囲の番を 1 つだけ扱う。反映していない番が複数あれば、古い順に 1 つずつ続けて行う
- 更新の仕事を積むきっかけは、ランナーの合図 `turnEnded` である (`features/runtime.md`「ランナーの中の合図」)
- ランナーは起動時に、`recap_seq` が最後の `turn_end` の `seq` より前の会話を探し、更新の仕事を積み直す
- 積み直すのは、最後の `turn_end` より後に `recap_failed_at` が立っていない会話だけとする。失敗した会話は、次の番の終わりまで待つ
- 積み直さないと、再起動で消えた仕事の会話が一覧の作業中に残り、通知も出ない (`features/inbox.md`)
- 小さいモデルの呼び出しは、FEASIBILITY.md「PoC 結果 > summary-ai-cost」の推奨アプローチの設定で行う (Haiku、ツールなし、ユーザー設定を読まない、記録を残さない、1 回だけ応答させる、題名を渡す)
- 呼び出しは、本書の Port (要約の呼び出し) を通す。テストでは台本どおりの結果を返す偽物に差し替える

渡すものと返させるもの:

| 渡すもの | 中身 |
| --- | --- |
| 目次 | 章の番号と名前 |
| 決まったこと | 項目の番号・種類・内容 |
| 未回答の文章の質問 | 質問の番号と文 |
| 新しい番 | 開発者の発言と AI の発言を行に分け、行ごとに番号を付けたもの。ツールの実行は「ツール: <名前>(<対象>)」の 1 行にして番号を付けない |

| 返させるもの | 形 | アプリが当てる先 |
| --- | --- | --- |
| 章 | 今の章に続けるか、新しい章を始めて名前を付けるか | 新しい章なら、その番の最初のイベントを `start_seq` にして `toc_entries` に足す |
| 決まったことの追加 | 種類、内容、理由 (任意)、根拠の行の番号 | ファイルに項目を足し、根拠の行のイベントの `seq` を書く |
| 決まったことの変化 | 変わった項目の番号と、変わった先 (足した項目) | 変わった項目に `→ D<番号>` を付ける |
| 質問の追加 | AI の最後の発言の行の番号 | その行の文をそのまま `questions` に足す。`kind` は `text`、`seq` はその発言の `seq` とする |
| 質問の回答済み | 質問の番号 | `questions` の `answered` を立てる |

- 返された結果は Zod のスキーマで確かめる。形が合わないか、存在しない番号を指すときは、1 回だけ呼び直す
- 質問は行の番号で選ばせ、アプリが行の文をそのまま写す。こうして AI の文を要約せずに並べる (BR-013)
- 最初の番は、必ず新しい章を始める
- 更新は、既存の章の名前と区切り、既存の項目の内容を書き換えない (変わった項目には変わった先の印を足すだけ)。開発者が直した内容は、以後の更新でも保たれる (UC-003 D)
- 章の名前は 30 文字まで、項目の内容と理由はそれぞれ 200 文字までとし、超えた分は切る
- ランナーは決定ファイルを先に保存する。そのあと同じトランザクションで `toc_entries` と `questions` を書き、`conversations.recap_seq` を番の最後の `seq` まで進める
- 決定ファイルを置き換える前に、ランナーは状態のディレクトリの `runner/recap/` (`features/operations.md`「データの置き場所」) に差分と置換前後のハッシュを保存する。差分は会話 ID と番の最後の `seq`、イベントのハッシュで照合する
- ランナーは置換時に v3 の版の印を先頭行に書き、その番の適用を記録する。画面の保存もこの印を保つ
- 再開時は置換後のハッシュか適用印が合えば、決定ファイルを保ち、SQLite の反映だけを行う。置換前のハッシュが合えば、保存した差分をファイルに当てる
- どちらも確認できないときは、外部で編集したファイルを保ち、更新に失敗した状態にする。SQLite を反映したら、一時保存した差分を消す
- 更新の結果は `/ws` で配信し、開いている直近・目次・決まったことの表示を読み直させる

失敗したとき:

- 呼び出しが 30 秒で終わらない、呼び直しても形が合わない、ファイルに書けない、のどれかで失敗とする
- 失敗したら `conversations.recap_failed_at` に時刻を書き、`recap_seq` は進めない。目次はそれまでの内容のまま残る
- SQLite の書き込みが競合して失敗の時刻を書けないか消せないときは、同じ仕事で書き込みを再試行する
- 失敗の時刻を書き直すのを待つ間に次の番が終わるか作り直しの依頼が来たら、古い失敗の保存をやめ、未反映の番から更新を再開する。ランナーの終了時は待機も終える
- 次の番の終わりに、反映していない番から自動でやり直す (P2)
- 開発者が「目次を作り直す」を選ぶと、すぐに同じやり直しをする (UC-003 E1)。全文を渡し直す作り方はしない

### 会話の AI が一覧を読む

- 会話の実行を開くとき、追加の指示として次の文を渡す (`features/conversation.md`「AI の実行の設定」)。「この会話で決まったことの一覧は <ファイルの絶対パス> にある。前に決めたことを尋ねられたら、このファイルを読んで答える。目次はツール recap_read で読める。」
- 会話が worktree で動くときは、プロジェクトのディレクトリを、AI が読める追加のディレクトリとして渡す
- アプリのツール `recap_read` は、その会話の目次 (章の番号・名前・範囲) と、決まったことの一覧 (ファイルの中身) を文字列で返す。引数は取らない
- `recap_read` は、`features/issue.md`「AI に渡すツール」のアプリのツールと同じ MCP サーバーに載せる

### 検索

- 目次か決まったことの一覧を開いているウィンドウで / を押すと、ステータス行に検索の入力が出る。Enter で検索する
- 検索の結果は右のウィンドウに出し、表示の履歴に積む。Ctrl+h で検索の前の表示へ戻る
- 結果は「章 n」「決まったこと n」「本文 n」の 3 つの見出しに分けて、一致した行を並べる。行で Enter を押すと、本文のその場所へ移る
- 一致は、文字列をそのまま含むかで判定する。語が小文字だけなら大文字と小文字を区別せず、大文字を含めば区別する
- 本文は、主のウィンドウに読み込んだ会話の行を対象にする。畳んだ差分の行も含める
- 本文の結果は 200 件までを出し、超えた分は「ほか n 件」の 1 行にまとめる
- 主のウィンドウとほかの表示の / は、Vim と同じバッファの中の検索のままとする

### 目次と一覧を直す

| 操作 | 起きること |
| --- | --- |
| 目次の章の行で cc | 入力欄に章の名前が入って開く。決めると名前を直す |
| 主のウィンドウで、章を始めたい行にカーソルを置いて :toc start <章の番号> | その章の始まりを、カーソルのある行のイベントに移す |
| 決まったことの行で cc | 入力欄に「<種類>: <内容>」が入って開く。決めると内容を直す。種類も書き換えられる |
| 決まったことの行で dd | その項目をファイルから消す。u で戻す |

- 章の始まりは、前の章の始まりより後で、次の章の始まりより前の位置にだけ移せる。1 章の始まりは動かせない
- 直した結果は、目次は `toc_entries` に、決まったことはファイルに書く。ファイルは画面のサーバーが書く

## API

DESIGN.md「API 一覧」のうち本機能の分を書く。エラーの形と共通のコードは DESIGN.md「横断規約 > エラー応答」に従う。入出力の Zod のスキーマは `src/shared/recap/api.ts` に置く。

### POST /api/conversations/:id/read

```json
{ "readSeq": 128, "position": 96 }
```

- どちらも省略できる。`readSeq` は保存済みの値より大きいときだけ書き、`last_seq` を超える値は `last_seq` にする
- 204
- 404 `not_found`

### GET /api/conversations/:id/recap

```json
{
  "lastUserMessage": { "seq": 96, "text": "在庫の引き当ても同じ API でやりたい。" },
  "questions": [{ "id": "01J...", "seq": 121, "kind": "choice", "text": "Q1. 期限切れの引き当てを戻す方法はどちらにしますか?" }],
  "pendingPermission": null,
  "draft": { "exists": true },
  "counts": { "stock": 2, "threads": 1, "activeThreads": 1, "queue": 0 },
  "lastReadSeq": 120,
  "lastPosition": 96,
  "state": { "reflectedSeq": 120, "failedAt": null, "updating": true }
}
```

- `questions` は未回答のものだけを、`seq` の順、同じイベントの中は出てきた順に返す
- `state.reflectedSeq` は `recap_seq`、`state.failedAt` は `recap_failed_at` である
- `state.updating` は、次の 2 つを両方満たすとき true とする
  - `recap_seq` が、最後の `turn_end` の `seq` より小さい
  - `recap_failed_at` が空か、その `turn_end` の `created_at` より前である
- `kind` は `choice` (選択式) / `text` (文章の質問) とする
- 404 `not_found`

### GET /api/conversations/:id/toc

- 200: `{ "chapters": [{ "position": 1, "title": "必要な機能の整理", "startSeq": 1, "endSeq": 8, "decisions": [{ "id": "D1", "text": "機能は検索・作成・取り消しの 3 つにする" }] }], "state": <GET recap と同じ形> }`
- 最後の章の `endSeq` は null とする
- 404 `not_found`

### PATCH /api/conversations/:id/toc/:position

- 本文: `{ "title": "在庫の引き当て", "startSeq": 52, "base": { "title": "在庫", "startSeq": 48 } }`。`title` と `startSeq` はどちらか一方だけでもよい
- `base` は、画面が目次を読んだときの章の名前と始まりである
- 200: GET toc と同じ形
- 400 `invalid_input`: 名前が空か 60 文字を超える。`startSeq` が前後の章の始まりの間に無い。1 章の始まりを動かそうとした
- 404 `not_found`: 章が無い
- 409 `conflict`: 章の名前か始まりが `base` と違う。画面は目次を読み直し、直した内容を入力欄に残す

### GET /api/conversations/:id/decisions

```json
{
  "path": "docs/decisions/01JDX4Q8ZK3W7M2N5P6R9T0V1A.md",
  "exists": true,
  "hash": "9f2c...",
  "items": [{ "id": "D2", "kind": "decision", "text": "取り消しは開始の 24 時間前までにする", "reason": null, "seq": 9, "changedTo": "D5" }],
  "state": { "reflectedSeq": 120, "failedAt": null, "updating": false }
}
```

- `kind` は `decision` / `rejected` / `pending` とする
- ファイルが無いときは `exists` を false、`items` を空、`hash` を null にする
- 404 `not_found`: 会話が無い
- 500 `internal`: プロジェクトのディレクトリが読めない。`message` にパスを入れる

### PUT /api/conversations/:id/decisions

- 本文: `{ "baseHash": "9f2c...", "items": [<GET と同じ形の項目>] }`。項目の並びと内容で、ファイルの項目を置き換える
- 送れるのは、項目の直し・削除と、消した項目を同じ番号で戻すことだけとする。番号はファイルの中で重複しなければよい
- 200: GET decisions と同じ形
- 400 `invalid_input`: 内容が空か 200 文字を超える。番号が重複する。`changedTo` が無い番号を指す
- 409 `conflict`: ファイルが `baseHash` のあとで変わった。画面は読み直して、直した内容を入力欄に残す

### POST /api/conversations/:id/recap/rebuild

- 反映していない番から、更新をやり直す。画面のサーバーは、ランナーの口 `POST /conversations/:id/recap/rebuild` に渡す (`src/shared/ipc.ts` に足す)
- 202: `{ "state": <GET recap と同じ形> }`
- 409 `conflict`: 反映していない番が無い
- 503 `runner_unavailable`: ランナーにつながらない

| 決まったことのファイル | ランナー (番ごとの更新) と画面のサーバー (開発者が直す)。「決まったことのファイル」の SHA-256 の比べ方で直列にする |

`toc_entries` は 2 つのプロセスが書く。ランナーは行を足すだけで、既存の行を書き換えない。どちらも前の変化を上書きしないように、次のように書く。

- 画面のサーバーは、画面が読んだときの `title` と `start_seq` (`PATCH` の `base`) を条件にして更新する。合わなければ 409 `conflict` を返す
- 画面のサーバーは、前後の章の始まりとの順を、更新と同じトランザクションの中で確かめる
- ランナーは、新しい章の `start_seq` が最後の章の始まりより後であることを、足すトランザクションの中で確かめる
- 後でなければ (開発者が最後の章の始まりを新しい番の中へ移した)、新しい章を足さずに今の章に続ける

## エッジケースの決定

1. 空・最小データ: AI の応答が 1 件も無い会話では、区切りも直近も出さない。目次が空なら「最初の応答が終わると、目次ができます。」、決まったことのファイルが無ければ「まだ決まったことはありません。」を出す。質問が無ければ「判断すること 0」の見出しの下に「ありません」を出す
2. 上限・境界値: 章の名前は更新で 30 文字、手で直すときは 60 文字まで。項目の内容と理由は 200 文字まで。検索の本文の結果は 200 件まで。番の数に上限は設けず、反映していない番は 1 つずつ続けて行う。1 回の更新は 30 秒で打ち切る
3. エラー時に利用者へ見えるもの: 更新の失敗は目次と決まったことの表示の中に出し、エラーのお知らせは出さない (番のたびに出るのを避ける)。修正の保存の失敗は `message` をエラーのお知らせに出し、直した内容を入力欄に残す。ファイルが読めないときは、決まったことの表示にパスと理由を出す
4. 並行操作・二重実行: 同じ会話の更新は 1 つずつ順に行う。作り直しは、更新の仕事が積まれていればその仕事に合流させ、二重に呼ばない。ファイルの書き込みは SHA-256 を比べてから置き換え、アプリでの修正がぶつかれば 409 にする。2 つのタブの既読は大きい方を残し、読んでいた位置は後から届いた方を残す
5. 再表示時の整合: 直近・目次・決まったことは開くたびに API で読み直す。更新の配信を受けたら、開いている表示を読み直す。決まったことはファイルを正本とし、開発者がエディターでファイルを直しても、次に開いたときに反映される
6. 表示の寿命: 「ここから未読」の区切りは、会話の画面を離れると消え、再読み込みでは消えない。直近は別の会話へ移ると閉じる。更新の失敗の表示は、次の更新を始めると消え、その更新も失敗するとまた出る。「いまここ」はカーソルのある章に付き、カーソルとともに動く
7. 送る前のデータ: 章の名前と決まったことの修正は、入力欄で決めた時点で保存する。保存に失敗したら、入力欄の中身を残す。区切りの位置と前回読んでいた位置の写しはタブの中 (sessionStorage) に置き、会話から離れると消す
8. 状態の移り変わり: 番が終わると「更新中」になり、反映できたら「反映済み」、失敗したら「失敗」に移る。失敗は、次の番の終わりか作り直しで「更新中」に戻る。文章の質問は、更新が回答済みと判定すると一覧から消える。選択式の質問は、回答を送ると消える
9. 自動で進むこと: 番の終わりの更新と、失敗したあとの次の番の終わりでのやり直しを自動で行う。ランナーの起動時には、再起動で消えた更新を積み直す。決まったことのファイルのコミットは自動で行わない
10. 端末と画面をまたぐこと: 既読の位置と前回読んでいた位置はサーバーに置き、どの端末でも同じにする (P3)。区切りの位置、右のウィンドウで開いている表示、カーソルはタブごとに持つ。目次と決まったことの修正はサーバーとファイルに置き、どの端末でも同じに見える
11. 並びと数え方: 質問の一覧は `seq` の順、同じイベントの中は出てきた順。目次は章の番号の順。決まったことはファイルの行の順。検索の結果は見出しごとに本文の順。直近の件数は、ストックは未送信のもの、スレッドは終えたものを含む数と動いているものの数

- 「決定が後で変わったとき…」の結合のテストは、変化を返す台本で更新を流し、ファイルの元の項目に `→ D<番号>` が付き、GET の `changedTo` に出ることを確かめる
- 「会話の AI に前に決めたことを尋ねると…」の結合のテストは、会話の実行に渡す追加の指示にファイルの絶対パスが入ることと、`recap_read` がファイルの中身を返すことを確かめる。本物の AI の答えは確かめない
- E2E は、前提データ (イベント、目次、文章の質問、決まったことのファイル) で未読のある会話を用意し、一覧と会話の層をまたいで通す
  - 一覧からその会話を開き、未読の先頭が出ることを確かめる
  - 直近の質問を選んで本文のその質問へ移り、続けて目次の章と決まったことの 1 件を選んで、カーソルがその行へ移ることを確かめる
  - 最後に回答を書いて送り、会話に開発者の発言が出ることを確かめる

E2E 対象動線: （US-024）会話を開いてから、質問・章・決定を選んで本文へ移動するまでを、Vim と同じ操作感のキーボード操作だけで行える
