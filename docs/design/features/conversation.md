# 会話

- 種別: 機能設計書
- 対象 UC: UC-002 (docs/design/USECASES.md)

## 何を作るか

開発者が会話で AI に指示を送り、AI の発言・ツールの実行・差分を読み、質問と許可の確認に答える機能。

**使う人**: 開発者 (PC のブラウザで、キーボードだけで操作する)

**流れ**:

1. プロジェクトを選んで会話を始める。既定はプロジェクトのディレクトリで、worktree を作るか選ぶこともできる
2. i で入力欄を開き、指示を書く。/ でスキルの候補を出す。画像は貼り付けると入力欄に縮小で並び、確かめて要らない画像を外せる。Mac の Ctrl+v で貼れるのは、ページを HTTPS などの安全な形で開いたときだけで、ふだんは Cmd+V で貼る
3. 送ると、AI の発言・ツールの実行・差分が、届いた順に会話に並ぶ。ツールの結果に含まれる画像 (スクリーンショットなど) は、文字ではなく画像で出る
4. AI の選択式の質問には、選択肢を選ぶか文章を書き、まとめて 1 通で送る
5. 応答が終わると、会話は判断待ちか指示待ちになる

**主な決まり**:

- AI が作業中に送った指示は預かり、番が正常に終わったときに、書いた順に 1 通にまとめて届ける。届く前なら入力欄に呼び出して直せて、取り消せる (BR-009、BR-103)
- 割り込みで送ると AI を止め、預かっていた指示を新しい指示の前に付けて、すぐに届ける。止めたときと失敗で止まったときは、預かった指示を届けずに残す (BR-088)
- 利用枠切れで止まった作業は、枠が戻ると自動で再開する。API のエラーや失敗で止まった作業は、開発者が再開を選ぶまで動かさない (BR-091)
- 選んだ選択肢と書いた回答は、送るまでサーバーに残り、どの端末でも同じに見える。答えていない質問があれば、送る前に確かめる (BR-089、BR-090)
- 書きかけの入力は会話ごとに 1 つをサーバーに残す。2 つの端末で書いたときは後から書いた方を残し、置き換えられた端末に知らせる (BR-094)
- 送信に失敗した内容と、接続が切れているあいだに書いた内容は、未送信として残す。つながっても自動では送らない (BR-092)
- 許可の扱いが既定のプロジェクトでは、AI は許可の確認を出さずに作業する。Claude Code のユーザー設定で確認するとしたルールに当たる操作だけは確認を出す (BR-007)

## 入出力と振る舞い

### この機能の前提

- 会話のイベントの保存、配信、ランナーへの操作の送り方、Agent SDK の Port と偽物は `features/runtime.md` が正本である。本書は、そのイベントをどう表示し、操作をどう扱うかを決める
- 主のウィンドウ・入力欄・メニューの行の作りは `features/buffer-ui.md` が正本である。本書は、会話の画面に出す行と、会話に固有のキーを決める
- 会話を閉じる・削除する・閉じた会話の一覧は `features/conversation-lifecycle.md`、worktree の作成は `features/worktree-terminal.md`、ストックとスレッドは `features/stock-thread.md` が持つ
- 未読の区切り・直近・目次・決まったこと・既読の位置は `features/recap.md` が持つ。会話を開いたときにカーソルを置く行も recap.md が決める
- 会話は、`conversations.run_state` と `conversations.stop_reason` で状態を持つ (DESIGN.md「データスキーマ」)。一覧のセクションへの振り分けは `features/inbox.md` が決める
- AI は、画面を開いているかどうかに関係なく動き続ける (BR-011)。画面を閉じても、ランナーは同じ実行を続ける

### 状態と止まった理由

ランナーは、会話の状態を次の表のとおりに移す。`stop_reason` は `stopped` / `failed` / `usage_limited` のときだけ値を持ち、ほかの状態では空にする。

| `run_state` | `stop_reason` | 移るきっかけ | 会話の末尾に出す行 | 開発者ができること |
| --- | --- | --- | --- | --- |
| `idle` | 空 | 番が正常に終わった。会話を作った直後 | なし | 指示を送る |
| `working` | 空 | 指示を届けた。再開した | ウィンドウの下端に、動く印と「考え中」か「ツールを実行中」と経過を出す。issue では工程を、ツールを使った後は最後にしたことを続ける (例: 「✻ 考え中… 8秒」「✻ ツールを実行中… 2分5秒 / 実装 11分 / 最後にしたこと: Bash(npm test -- csv)」) | 預ける、割り込む、止める |
| `waiting_answer` | 空 | AI が選択式の質問を出した | 質問と選択肢のメニューの行 | 答える、割り込む、止める |
| `waiting_permission` | 空 | AI が許可の確認を求めた | 許可の確認のメニューの行 | 許可する、拒否する、割り込む、止める |
| `stopped` | `user` | 開発者が止めた。プロジェクトの登録を解除した | 「止めました」の区切りの行 | 指示を送る |
| `stopped` | `restarted` | ランナーが再起動した (`working` / `waiting_answer` / `waiting_permission` だった会話) | 「作業が止まりました (AI を動かすプロセスが再起動しました)」と「再開する」 | 再開する、指示を送る |
| `failed` | `api_error` | API のエラーで番が終わった | 「止まっています: <エラーの説明>」と「再開する」 | 再開する、指示を送る |
| `failed` | `error` | API のエラー以外の失敗で番が終わった。自動フローが段階の worktree を作れなかった (`features/issue-flow.md`) | 同上 | 再開する、指示を送る |
| `failed` | `credits_required` | クレジットの購入が要る | 「止まっています: クレジットの購入が要ります」と「再開する」 | 再開する、指示を送る |
| `usage_limited` | `usage_limit` | 利用枠を使い切った | 「止まっています: 利用枠を使い切りました。<時刻> に戻り、自動で再開します」と「いま再開する」 | 再開する、指示を送る |
| `usage_limited` (閉じた会話) | `usage_limit` | 利用枠切れで止まったまま閉じた | 「利用枠切れで止まっています。続きを送ると再開します」と「再開する」 | 再開する、指示を送る |

- 記録の `stopped` の理由も、`stop_reason` と同じ値で書く (DESIGN.md「データスキーマ」)
- 閉じると利用枠の戻りを待つタイマーが外れるので、閉じた会話は枠が戻っても自動では再開しない (`features/conversation-lifecycle.md`)
- 割り込みで続く指示を受理した場合は、その指示で `working` に移る。受理できなかった場合の停止記録と表示は、`features/runtime.md`「Agent SDK のメッセージからの写し方」の番の終わりの表に従う
- 利用枠切れの判定は DESIGN.md「既知の制約」の規則に従う。戻る時刻は `conversations.resets_at` に Unix ミリ秒で持つ。時刻が無いときは、末尾の行の時刻の代わりに「15 分ごとに再開を試みます」と出す
- `failed` の説明には、エラーの種類を日本語にした 1 文を出す (例: 「API が混み合っています」「認証に失敗しました。この Mac の Claude Code にログインし直してください」)

### 開発者の操作と画面に起きること

画面は UI_SKETCH.html の `pc-conv--recent`・`pc-conv--answers`・`pc-conv--input`・`pc-issue-working`・`pc-issue-working--input`・`pc-issue-working--queue-edit`・`pc-issue-stopped`・`pc-home--switch` を手本にする。

| 操作 | 画面に起きること |
| --- | --- |
| 右のウィンドウ「会話を始める・切り替える」(Space n) か、プロジェクトの画面で「会話を始める」 | プロジェクトのディレクトリで、空の会話が開く。入力欄は閉じたまま。お知らせ「<プロジェクト> で会話を始めました (プロジェクトのディレクトリ)」を出す |
| 同じ一覧で「worktree を作って会話を始める」 | 新しい worktree を作り、その中で動く空の会話が開く。お知らせ「worktree <名前> を作り、その中で会話を始めました」を出す |
| worktree の一覧 (Space k) の行で Enter | 開いている会話の作業場所を、その worktree に切り替える (`features/worktree-terminal.md`「作業場所の切り替え」) |
| 会話で i | 入力欄が開き、書きかけがあれば続きから書ける。Insert モードで始まる |
| 入力欄 (Normal) で Enter | 送る。AI が `idle` / `stopped` / `failed` / `usage_limited` ならすぐ届け、開発者の発言として会話に出し、お知らせ「送りました」を出す。画像があれば「画像 n 件と一緒に送りました」とする。作業中なら預け、お知らせ「預けました。今の作業が終わると届きます」を出す |
| 入力欄 (Insert、Normal) で Ctrl+Enter か Alt+Enter | AI が作業中なら割り込み、お知らせ「AI を止めて、すぐに送りました」を出す。届く前の指示を前に付けたときは「AI を止めて、届く前の指示 n 件と一緒にすぐに送りました」とする。入力欄が空で届く前の指示があるときは、届く前の指示だけを届け、「AI を止めて、届く前の指示 n 件をすぐに送りました」とする。作業中でなければ Normal の Enter と同じに送る |
| 入力欄で ↑ (カーソルが先頭の行にあり、届く前の指示があるとき) | 書きかけを脇に置き、いちばん新しい届く前の指示を入力欄に出して直せるようにする。欄の名前は「預けた指示を直す (k / n 件目)」になる。決まりは「届く前の指示を入力欄で直す」 |
| 入力欄で Esc か Ctrl+[ | Insert なら Normal へ移る。Normal なら入力欄を閉じ、書きかけを残す。書きかけがあれば、お知らせ「書きかけを残しました。i で続きを書けます」を出す |
| 入力欄の先頭で / を打つ | スキルの候補を、打った文字に前方一致で絞って入力欄の上に出す。Tab で先頭の候補を入れる |
| 入力欄 (Insert) で Ctrl+v | クリップボードの画像を上げ、入力欄に縮小を番号付きで並べ、下の段に「画像 n 件 (送信時に一緒に送る)」と出す。クリップボードに画像が無く文字があれば、カーソルの位置に文字を入れる。macOS で `http://macstudio:<port>` を開いているときは貼れず、Cmd+V を案内する (「貼り付けた画像」) |
| 入力欄でブラウザの貼り付け (macOS の Cmd+V など) | Ctrl+v と同じに、画像を上げて縮小を並べる |
| 入力欄 (Normal) で Ctrl+w j のあと、h / l で縮小を選んで d | 選んだ画像を外し、縮小を詰めて番号を振り直す。お知らせ「画像 <番号> を外しました」を出す。Enter で元の大きさを新しいタブに開く (「入力欄で確かめて外す」) |
| コマンド :images clear | 貼った画像をすべて外す |
| ツールの結果の画像の行で Enter | その画像を、元の大きさでブラウザの新しいタブに開く |
| 選択肢の行で Enter | その選択肢を選ぶ。行の説明が「この選択肢を選ぶ」から「✓ 選んだ (まだ送っていない)」に変わる。選んだ行でもう一度 Enter を押すと外れる。1 つだけ選ぶ質問で別の選択肢を選ぶと、前の選択は外れる |
| 回答を送ったあとの選択肢の行で Enter | 何も変えず、お知らせ「この質問には、回答を送ってあります」を出す。行の説明は「✓ 送った回答」になる |
| 「Qn に文章で答える」の行で Enter | 入力欄が開く。決めると、質問の下に「→ あなたの回答 (まだ送っていない): <文>」と出し、お知らせ「回答を書きました。「回答をまとめて送る」で送ります」を出す |
| 「回答をまとめて送る (n / m 件)」の行で Enter | 全部に答えていれば送り、お知らせ「回答 n 件を 1 通にまとめて送りました」を出す。答えていない質問があれば、確認「答えていない質問が n 件あります。このまま送りますか? (y / n)」を出し、y で送る。1 問も答えていなければ送らず、お知らせ「回答がまだありません。選択肢を選ぶか、文章で答えてください」を出す |
| 許可の確認の「許可する」か「拒否する」の行で Enter | 答えを AI に返し、会話の末尾に答えた結果を 1 行出す |
| 届く前の指示の行で cc / dd | cc は、入力欄で ↑ を押して選んだときと同じに、その指示を入力欄に出して直せるようにする。dd はその指示を取り消し、お知らせ「預けた指示を取り消しました。u で戻せます」を出す。u を押すと、同じ指示を預け直す。ストックから送った指示はストックに戻り、入力欄から送った指示は書きかけに戻る |
| 「届く前の指示を送る」の行で Enter | AI が作業中でなければ、残っている指示を書いた順に 1 通にまとめて届ける |
| Space x か :stop | AI を止め、お知らせ「<送り先> の AI を止めました。作業は保存され、指示待ちになります」を出す。<送り先> は `会話: <題名>` か `#<番号> <題名>` である。確認は挟まない (止めても指示を送れば続けられる) |
| 「再開する」の行で Enter | 止まった段階から続ける |
| ツールの実行の行で Enter | ファイルを対象にするツール (Read・Edit・Write など) は、そのファイルを開く (`features/files.md`)。issue のツールは、その issue を開く |
| 畳んだ差分の「残り n 行」の行で Enter か zo | その差分を開く |
| 開いた差分の行で zc | 25 行を超える差分を、もう一度畳む |

- ツールの行の issue のツールは、名前が `mcp__sukuna__issue_` で始まるものとする。開く issue は、`issue_create` なら結果の番号、`issue_get`・`issue_update`・`issue_comment` なら引数の `number` で決める。`issue_list` の行は何も開かない
- ツールの行に印があるときは、Enter で印の動きを先にする (`features/stock-thread.md`「印」)
- 会話の画面のキーは、`features/buffer-ui.md` のキーの割り当ての仕組みで変えられる
- 選択肢の行にカーソルがあるとき、ステータス行のキーの案内は「Enter この選択肢を選ぶ (もう一度で外す) / 番号 Enter 番号で選ぶ / i 入力」とする
- 「回答をまとめて送る」の行の説明は、全部に答えていれば「1 通にまとめて AI に届く」、答えていない質問があれば「答えていない質問が n 件ある」とする
- 会話の題名は、最初に送った指示の 1 行目の先頭 40 文字とする。指示を送るまでの題名は「新しい会話」とする

右のウィンドウ「会話を始める・切り替える」には、プロジェクトごとに次の行をこの順に並べる。

1. プロジェクトの名前の見出しの行
2. 閉じていない会話 (`chat`) の行「会話: <題名>」
3. 下書き・完了・取り下げ以外の issue の行「#<番号> <題名>」
4. メニューの行「<プロジェクト> で会話を始める」
5. いま開いている画面のプロジェクトにだけ、メニューの行「worktree を作って会話を始める」

- 会話と issue の行で Enter を押すと、それを開く。issue の開き方は一覧と同じである (`features/inbox.md`)

### 会話に並べる行

イベントは `seq` の順に並べる。行の種類と見た目は次のとおりで、作りは `features/buffer-ui.md` の行の種類に当てる。

| イベント | 出す行 |
| --- | --- |
| 開発者の発言 | 「あなた」の札の行のあとに本文の行。画像があれば「画像 n 件」の行。アプリが前置きを付けた文 (メニューからの差し戻しなど) も、前置きを含めて出す |
| 自動フローが送った文 (`origin` が `flow`) | 「自動フローが指示を送りました」の区切りの行。開発者の発言としては出さない |
| 再開 (記録の `resumed` と、`origin` が `resume` の発言) | 「再開しました」の区切りの行を 1 つ出す。再開の文は開発者の発言としては出さない |
| 確定事項の案を求めた文 (`origin` が `finish_proposal`) | 「確定事項の案を求めました」の区切りの行。開発者の発言としては出さない (`features/stock-thread.md`「スレッドを終える」) |
| 回答を指示にした文 (`origin` が `answer_text`) | 出さない。同じ回答を「送った回答」の行で出す |
| AI の発言 (書きかけ) | 配信の `delta` を、会話の末尾の書きかけの区画に届いた順に足す。保存しないので、開き直すと出ない |
| AI の発言 | 「AI」の札の行のあとに本文の行。届くと、書きかけの区画を消してこの行に置き換える |
| ツールの実行 | 「● <ツール名>(<対象>)」の行。結果が届くと、その下に結果の行を足す (下の箇条「ツールの結果の行」)。結果に画像があれば、結果の行の下に画像を 1 枚ずつ出す (「ツールの結果の画像」) |
| ファイルの編集の差分 | ツールの行の下に、行番号付きの追加と削除の行。25 行を超える差分は先頭 10 行だけを出し、「残り n 行 (Enter か zo で開く)」の行で畳む |
| 選択式の質問 | 質問の文の行、選択肢のメニューの行、「Qn に文章で答える」の行、最後に「回答をまとめて送る (n / m 件)」の行 |
| 送った回答 | 「あなた」の札のあとに「Q1: <回答>」の形で 1 行ずつ |
| 許可の確認 | 「許可の確認: <ツール名>(<対象>)」の行と、「許可する」「拒否する」のメニューの行 |
| 止まったこと | 区切りの行 (状態の表の「会話の末尾に出す行」) |
| 届く前の指示 | 会話の末尾に「届く前の指示: <1 行目>」の行を書いた順に並べる。最後に「届く前の指示を送る」の行 (AI が作業中でないときだけ) |

- AI の発言の本文の行は、書きかけも含めて Markdown として整えて出す。行に `markdown` の印を付け、整え方は `features/buffer-ui.md`「行の種類と装飾の持ち方」に従う。記号はカーソルの行でだけ出す
- Markdown は発言ごとに読む。ある発言のコードの囲みが閉じていなくても、次の発言の見た目は変わらない
- 開発者の発言、ツールの行、差分の行は、Markdown として読まず、記号を含めてそのまま出す
- ツールの結果の行は、ターミナルの Claude Code と同じ形にする。結果の本文の先頭 3 行までを出し、長い出力で会話が埋まらないようにする
  - 1 行目は「  ⎿  <本文の 1 行目>」とする。2 行目と 3 行目は、空白 5 文字のあとに本文を置き、1 行目の本文と字の頭を揃える
  - 本文が 3 行を超えるときは、4 行目に「     … +<残りの行数> 行」を出す。本文がランナーで切り詰められていたら (`truncated`)、「… +<残りの行数> 行以上」とする。残りの行を開く操作は持たない
  - 本文の末尾の改行は行に数えない。本文が空か改行だけなら、「  ⎿  (出力なし)」の 1 行を出す
  - 本文を出した行は、本文の何行目か (0 から) を `seqLine` に持つ。「… +n 行」と「(出力なし)」の行は `seqLine` を持たず、引用の位置に使わない
  - 画像を含む結果は、文字のブロックをつないだ文を本文とする。文が無ければ、「(出力なし)」の代わりに「  ⎿  画像 n 件」(n は保存できた画像の数) を出す。1 枚も保存できなかったときは「  ⎿  画像 m 件 (表示できません)」(m は結果の中の画像の数) とする
- 番の途中の作業中の表示は、バッファの行ではなく、主のウィンドウの下端に出す。表示の文、印の動き、経過の求め方は `features/work-monitor.md`「作業中の会話の表示」が正本である
- 書きかけの区画、質問の区画、届く前の指示の行は、状態が変わるたびに書き換える。書き換えは会話の末尾の区画に限る (`features/buffer-ui.md`「末尾の区画」)
- 末尾の区画は、書きかけ (`reply`)、質問 (`question`)、届く前の指示 (`queue`) の順に並べる
- 書きかけの区画は、次の `assistant_text` か `turn_end` の記録が届いたら消す (`features/runtime.md`「配信 (`/ws`)」)
- 書きかけの区画の行は `seq` を持たないので、ストックの引用の位置に使わない
- 差分の開閉はタブごとに持つ

### 表示の追従と読み込み

- 会話を開くと、`GET /api/conversations/:id/events` を `after=0` から 2,000 件ずつ、最後まで続けて読む。読み終えるまで Skeleton を出す
- 開いたあとは、`/ws` の会話の購読で届いたイベントを末尾に足す。つなぎ直したときは、覚えている最後の `seq` の続きを API で読む (DESIGN.md「横断規約 > 配信」)
- AI の発言は、書きかけの文字 (`delta`) が届くたびに末尾の書きかけの区画に足し、逐次出す。保存は 1 件が届き終わったときだけなので、開き直すと保存済みの発言だけが出る
- 新しい行 (書きかけの文字を含む) が届いたとき、カーソルが末尾の行にあれば、カーソルを新しい末尾の行へ動かして表示を追う。末尾以外にあれば、カーソルも表示も動かさない (BR-093)

### 指示を届ける規則

開発者が送ったものと預かった指示は、次の 1 つの規則で届ける。

- AI が作業中 (`working` / `waiting_answer` / `waiting_permission`) のときに普通に送った指示は、`queued_instructions` に預ける
- 番が正常に終わったら、預かった指示を書いた順に改行 2 つでつなぎ、1 通にして届ける。各指示の画像も同じ 1 通に付ける
- 番が止まって終わったら (開発者の停止、失敗、利用枠切れ、再起動)、預かった指示は届けずに残す
- AI が作業中でないときに開発者が指示を送ったら、残っている預かった指示を前に付けて 1 通にして、すぐに届ける。「届く前の指示を送る」は、新しい指示なしで同じことをする
- 割り込みで送ったら、AI を止めてから、預かった指示を前に付けて 1 通にして、すぐに届ける。新しい指示の本文も画像も無い割り込みでは、預かった指示だけを 1 通にして届ける
- 再開は、預かった指示を届けない。再開した番が正常に終わったら、上の規則で届ける

ストックから送った指示も、本文と一緒に送った指示も、同じ規則で届けるか預ける。指示に結び付くストックの ID は、単数なら `queued_instructions.stock_item_id`、まとめて預けた場合は `delivery_context` に記録する。

- 預かった指示を届けたら、ランナーは同じトランザクションで、対象のストックすべての `sent_seq` に発言の `seq` を書く
- 預かった指示を取り消したら、画面のサーバーは、対象のストックすべてを `stocked` に戻す。開発者が送った本文・画像・相談の範囲も、同じトランザクションで書きかけに戻す
- 書きかけがあれば、その後ろに空行 1 つを挟んで足す。戻した書きかけの `updated_at` は取り消した時刻にし、`changed` の `draft` を配信する
- 預かった指示を直すと、取り消しで書きかけに戻る内容も最新の版になる。差し戻しの前置きやストックから組み立てた文は、書きかけと分けて保存する
- 取り消したタブで u を押すと、開発者が送った本文・画像と元のストックを一度の受付で預け直す。書きかけに戻した分は、復帰の受付と一緒に取り除く
- 書きかけの別の部分を編集しても、追記した指示の範囲を追跡し、u ではその範囲と添付だけを取り除く。戻した範囲または前後の同じ行を編集したら、書きかけを残して預け直さず、お知らせに理由を出す。別の行として追加した文は残す
- 復帰のときは、保存済みの書きかけと画面が確認した内容・時刻・書き手を照合する。ランナーは指示の受付と書きかけの書き換えを同じトランザクションで行う。照合に失敗したら、書きかけを保ってお知らせに理由を出す
- 復帰の応答を受け取れなかったら、u で同じ送信の識別子を使う。すでに受け付けていれば初回の結果が返る
- 復帰の応答を待つ間も、書きかけの別部分を編集できる。入力欄を閉じても、復帰が確定したら取り除いた範囲を反映して保存する
- 応答待ちには、戻した範囲と同じ行や添付を編集できず、入力欄から送信できない。操作すると、お知らせに復帰の結果を待つように出す
- 確定後の追加保存より先に別端末が書きかけを変えた場合は、その内容を保つ。この端末の追記も入力欄に残し、保存していないと知らせる
- 預け直した指示は、届く前の指示の列の最後に入る。AI が指示を待っているときに預け直すと、すぐに届く
- 預かった指示を直しても、元のストックの本文は変えない

issue の会話 (`kind` が `triage` / `design` / `impl`) へ開発者の指示を届ける前に、ランナーは `flow` の判定を表の上から順に通す。ストックの指示と、「届く前の指示を送る」も同じである。再開の操作も、表の 1 行目と 2 行目の判定を通す。

| 届けるときの issue | 判定 | 起きること |
| --- | --- | --- |
| 送った会話が、issue の担当の会話ではない (例: 実装中の issue の精査の会話) | 断る | 409 `conflict` と「この issue はいま <段階> の会話で進んでいます」などの文を返す。文は `features/issue.md` が決める。記録は読める |
| 停止中 (`failed`。`cause` が `worktree_failed`) | `retryStageWorktree` | `flow` が worktree を作り直し、段階の最初の指示と開発者の指示を 1 通にして届ける。再開では最初の指示だけを届ける。作り直せなければ指示を届けず、500 `worktree_failed` を返す (`features/issue-flow.md`「停止中から戻る」) |
| 設計レビュー (設計の会話) | `rejectDesign` | 差し戻しとして届け、issue を設計待ちにする (`features/design-review.md`「差し戻し」) |
| 停止中 (merge 前の確認、CI の失敗)、完了 (実装の会話) | `deliverImplInstruction` | issue を実装中に戻してから届ける (`features/pr-review.md`「指示を送ったときの移り変わり」) |
| そのほか | なし | 上の規則で届けるか預ける。issue の状態は `features/issue-flow.md` が決める |

- issue の担当の会話は、`features/issue.md`「担当の会話」の表で決める。<段階> はその会話の種類の名前 (精査・設計・実装) である
- `flow` の判定は、指示を送った時点で通す。AI が作業中で預かった指示を、番の終わりに届けるときは通し直さない

### 届く前の指示を入力欄で直す

開発者は、会話の入力欄から届く前の指示を呼び出して直し、そのまますぐに送れる。書きかけは、指示を直しているあいだも元のまま残る (BR-103)。

↑ と ↓ で指示を選べるのは、会話かスレッドの表示で i を押して開いた入力欄だけである。AI が作業中でなくても、届く前の指示が残っていれば選べる。ストックの指示と一緒に送る入力欄、差し戻しや確定事項の入力欄では、↑ と ↓ はカーソルを動かすだけにする。「先頭の行」と「末尾の行」は、改行で区切った行で数える。

| 操作 | 画面に起きること |
| --- | --- |
| 書きかけを書いている入力欄で ↑ (カーソルが先頭の行) | 書きかけを保存してから脇に置き、いちばん新しい (最後に預けた) 届く前の指示を出す。カーソルは本文の末尾に置き、モードは変えない。届く前の指示が無ければ、カーソルを動かすだけにする。書きかけを保存できないとき (接続が切れている、保存に失敗した) は移らず、理由をお知らせに出す |
| 指示を直している入力欄で ↑ (カーソルが先頭の行) | 1 つ古い指示へ移る。いちばん古い指示では何もしない |
| 指示を直している入力欄で ↓ (カーソルが末尾の行) | 1 つ新しい指示へ移る。いちばん新しい指示からは、脇に置いた書きかけに戻る |
| 指示を直している入力欄 (Normal) で Enter | 直した内容を保存して入力欄を閉じ、お知らせ「預けた指示を直しました」を出す |
| 指示を直している入力欄 (Insert、Normal) で Ctrl+Enter か Alt+Enter | 直した内容を保存してから、届く前の指示をすべて、書いた順に 1 通にまとめてすぐに届け、入力欄を閉じる。AI が作業中なら止めてから届け、お知らせ「AI を止めて、届く前の指示 n 件をすぐに送りました」を出す。作業中でなければ「届く前の指示を送る」と同じに届け、お知らせ「届く前の指示 n 件を送りました」を出す |
| 指示を直している入力欄 (Normal) で Esc | 直した内容を保存して入力欄を閉じる。次に i で開くと書きかけが出る |

- 指示を直しているあいだ、欄の名前は「預けた指示を直す (k / n 件目)」にする。k は古い方から数えた位置、n は届く前の指示の件数である
- 入力欄の下のヒントは次のとおりにする (並びと形は `features/buffer-ui.md`「入力欄」)
  - 書きかけを書いていて、届く前の指示があるとき: 「↑ 届く前の指示を直す」を足す
  - 指示を直しているとき: Enter の動詞を「直す」、Esc の説明を「閉じる (直した内容は残る)」にする。いちばん古い指示でなければ「↑ 前の指示へ」を足す。Ctrl+Enter の説明は、AI が作業中なら「AI を止めて届く前の指示をすぐ送る」、作業中でなければ「届く前の指示をすぐ送る」にし、作業中でなくても出す
- 直した内容は、別の指示へ移るとき、書きかけに戻るとき、閉じるとき、送るときに `PATCH /api/conversations/:id/queue/:itemId` で保存する。内容を変えていなければ保存しない
- 保存に失敗したら (404 を除く)、移らず・閉じず・送らずに今の指示に留まり、応答の `message` をエラーのお知らせに出す。直した内容は入力欄に残す
- Ctrl+Enter で、保存は通ったが届けるのに失敗したとき (ランナーにつながらない、issue の担当でない段階の会話など) は、入力欄を閉じずに今の指示に留まる。入力欄の下に「未送信: <失敗の理由>」を出し、もう一度 Ctrl+Enter で送れる
- 本文も画像も空にして保存しようとしたら、保存せずに今の指示に留まり、お知らせ「内容が空です。取り消すときは、届く前の指示の行で dd を押してください」を出す
- 指示を直しているあいだは、入力欄の内容を書きかけとして保存しない。書きかけはサーバーに残り、入力欄を閉じたあとも i で続きを書ける
- 書きかけに戻るときは、サーバーの最新の書きかけを出す。脇に置いているあいだに別のタブが書きかけを変えていれば、その内容を出し、お知らせ「別の端末で書いた内容に置き換わりました」を出す (「書きかけの入力と未送信」)
- 指示を直しているあいだに貼った画像は、直している指示に付く。「画像 n 件」の表示と :images clear も、直している指示の画像に効く。書きかけの画像は変わらない
- 直している指示が届く前の指示の列から消えたら (番の終わりに届いた、別のタブか dd で取り消された)、書きかけに戻る。消えたことは、配信で届いた列か、保存の 404 で知る。内容を変えていなければ、お知らせ「この指示は、もう届く前の指示にありません」だけを出す。内容を変えていれば、消え方で分ける
  - 届いたとき (その指示を含む開発者の発言が会話に出たとき): 直した内容を書きかけの後ろに空行 1 つを挟んで足し、お知らせ「この指示はもう届いていました。直した内容を書きかけの後ろに足しました」を出す
  - 取り消されたとき: 取り消しで書きかけに戻った元の本文を、直した内容に置き換え、お知らせ「この指示は取り消されました。直した内容を書きかけに戻しました」を出す。書きかけが別に変わっていて元の本文が見つからなければ、後ろに足す
  - このタブの dd で取り消したときは、置き換わりのお知らせ「別の端末で書いた内容に置き換わりました」を出さない
- ストックから預けた指示と、まとめて預けた指示は、開発者が書いた本文だけを入力欄に出す。前置きと引用は保つ (「PATCH /api/conversations/:id/queue/:itemId」)
- 取り消しの復帰の応答を待っているあいだは、↑ で指示を呼び出さない。押すと、お知らせに復帰の結果を待つように出す (「指示を届ける規則」)
- 別のタブで届く前の指示が増えたり減ったりしても、直している指示はそのまま直せる。k と n は、配信で届いた最新の列で数え直す
- すぐに届けるときも「指示を届ける規則」に従う。直した指示だけを先に届けることはしない

### 選択式の質問と許可の確認

- AI が選択式の質問を出したら、ランナーは答えを返すのを保留し、質問を `questions` に 1 問ずつ追加する (種類は選択式)。会話は `waiting_answer` になる
- 開発者が選んだ選択肢と書いた文は、`pending_answers` に保存する。届いた保存は `/ws` で配信し、ほかの端末の表示も変える (BR-090)
- まとめて送ると、ランナーは全問の答えを 1 回で AI に返す。答えの文字列は、選択肢だけなら選択肢の名前、文だけならその文、両方なら「<選択肢の名前>: <文>」とする
- 答えていない質問には「(開発者は答えなかった)」を返す
- 複数選べる質問は、選んだ選択肢の名前を「、」でつなぐ
- 送ったら、同じトランザクションで `pending_answers` を消し、選択式の `questions` を回答済みにする
- 質問に答える前に会話が止まったら (停止、再起動)、AI はその質問の答えを待たなくなる。送る前の回答は残す
- 待たなくなった質問の回答をまとめて送ると、普通の指示 (`origin` が `answer_text`) として届ける。文の形は `features/runtime.md`「ランナーの再起動」の「Q: … / A: …」とする
- 回答以外の指示を届けた番では、AI の発言、ツールの実行、選択式の質問、許可の確認のうち、最初の記録を保存した時点を応答の開始とする
- ランナーは、その記録を保存するトランザクションで、前の番の選択式の質問を回答済みにし、送る前の回答を消す
- 画面は同じ記録を受け取ったときに、前の質問を会話の履歴に移す。送らずに履歴に移した質問の選択肢は、操作できない行で表示する
- 発言の書きかけを受け取った段階や、出力を保存せずに番を終えた場合は、前の回答を残す。同じ番の質問への回答も残す
- 保存済みの履歴から次の応答の開始を確認できる場合は、前の番の回答を読み出しと送信の対象から外す
- 許可の確認は、許可の扱いを既定から変えたプロジェクトでは、AI がツールの実行の許可を求めたときに出す (BR-063)。既定のプロジェクトでも、Claude Code のユーザー設定で確認するとしたルールに当たる操作は、同じ形で出す
- 許可の確認が出たら、ランナーは答えを返すのを保留し、会話を `waiting_permission` にする。答えを待つ期限は設けない
- 質問か許可の確認を保留しているあいだに割り込みか停止が来たら、ランナーは保留を拒否で解いてから AI を止める。拒否の理由は「開発者が割り込んだ」とする

### 停止・割り込み・再開

- 止める操作は、AI の番を止め、その会話でバックグラウンドで動いているタスクも止める (DESIGN.md「既知の制約」)
- 止めたあとの指示は、同じ会話の続きとして届ける。会話の文脈は保つ
- 再開の操作は、決まった文「中断したところから続けてください。」を AI に届け、会話に「再開しました」の区切りの行を出す。送り方は `features/runtime.md`「再開と利用枠の戻り」に従う
- 利用枠切れで止まったら、ランナーは戻る時刻の 1 分後に再開する。時刻が無いときは 15 分ごとに再開を試みる。再開して再び利用枠切れになったら、新しい時刻で待ち直す
- 自動フローの会話 (`kind` が `triage` / `design` / `impl`) は、再開する前に、再開してよいかを `flow` に問う
- プロジェクトが一時停止のときと、その段階を自動で処理する段階から外しているときは再開せず、解除のあとの `flow` の評価で再開する (`features/issue-flow.md`「AI が止まったとき」)
- クレジットの購入が要る止まり方 (`credits_required`) は、時刻を待っても戻らないので、自動では再開しない
- ランナーが再起動したら、`working` / `waiting_answer` / `waiting_permission` だった会話を、種類を問わず `stopped` と `restarted` にする
- 開発者が始めた会話 (`kind` が `chat` と `thread`) は、再開か指示が届くまで動かさない
- 自動フローの会話の続きは `features/issue-flow.md`「ランナーの再起動のあと」に従う

### 書きかけの入力と未送信

- 書きかけは、入力欄で文字か画像が変わってから 500 ミリ秒たったときと、入力欄を閉じたとき、別の画面へ移るときに `PUT /api/conversations/:id/draft` で保存する (BR-094)
- 保存には、そのタブの識別子 (タブを開いたときに作る ULID) と、そのタブで最後に編集した時刻を付ける
- サーバーは、届いた編集の時刻が保存済みの時刻より新しいときだけ置き換える。後から書いた方を残すためである
- 古いために置き換えなかった保存には、保存済みの書きかけを返す。送ったあとに編集していないタブは、入力欄をその中身に置き換える
- 書きかけが別のタブの保存で変わったら、`/ws` で配信する
- 受け取ったタブに保存していない編集が無ければ、入力欄の中身を置き換え、「別の端末で書いた内容に置き換わりました」をお知らせに出す
- 保存していない編集があれば、入力欄は置き換えず、「別の端末で書き換えられました」をお知らせに出す。このタブが次に保存すると、後から書いた方として残る
- 送信に成功したら、書きかけを消す。送信に失敗したら、入力欄の中身を残し、入力欄の下に「未送信: <失敗の理由>」を出す (E3)
- 接続が切れているあいだは、書きかけをタブの中に持ち、つながったら最新のものを保存する。送る操作は失敗として扱い、未送信として残す (BR-092)
- 接続が戻っても、未送信の内容は自動では送らない。開発者が Enter で送る

### スキルの候補

- 候補は、`GET /api/conversations/:id` の応答の `commands` から出す。候補の行には、名前と説明の 1 行目を出す
- ランナーは、会話の実行を開くたびに Agent SDK からスキルとコマンドの一覧を受け取り、プロジェクトごとに最新のものを覚えておく
- その会話でまだ一覧を受け取っていないときは、同じプロジェクトで最後に受け取った一覧を返す。それも無いときは空を返し、候補の場所に「最初の指示を送ると候補が出ます」と出す
- 候補を選んだ指示は、書いた文字列のまま AI に届ける。スキルの手順は、端末の Claude Code と同じに AI が進める

### 画像

会話で扱う画像は 2 種類ある。開発者が入力欄に貼り、指示と一緒に AI へ送る「貼り付けた画像」と、AI のツールの結果に含まれる「ツールの結果の画像」(ブラウザのスクリーンショットなど) である。どちらもデータのディレクトリ (`features/operations.md`「データの置き場所」) の下のファイルに置き、画像の ID (ULID) で指す。置き場所、ファイルの名前、書くプロセスは `features/runtime.md`「書くプロセスの分担」が正本である。画面は、どちらの画像も `GET /api/conversations/:id/images/:imageId` で読み込んで表示する。

#### 貼り付けた画像

画像は、ブラウザの貼り付け (macOS の Cmd+V、Windows と Linux の Ctrl+V) と、macOS の Ctrl+v で入力欄に貼る。Ctrl+v は、入力欄が Insert のときに次の表のとおりに働く。

| 端末とページ | Insert で Ctrl+v を押したとき |
| --- | --- |
| Windows、Linux | アプリは Ctrl+v を受け取らず、ブラウザに渡す。ブラウザの貼り付けとして届くので、画像も文字も貼れる |
| macOS で、安全なオリジンのページ (HTTPS で開いたとき、Chrome の例外指定をしたとき) | アプリが Ctrl+v を受け取り、ブラウザのクリップボードの読み取り (Clipboard API の `read`) で中身を読む |
| macOS で、安全なオリジンでないページ (`http://macstudio:<port>` で開いたとき) | ブラウザはクリップボードを読ませない (DESIGN.md「既知の制約」)。アプリが Ctrl+v を受け取り、お知らせ「このページではクリップボードを読めません。Cmd+V で貼り付けてください」を error で出す |

決定: macOS の Ctrl+v だけをアプリが受け取り、ほかの端末ではブラウザに任せる
理由: Windows と Linux では Ctrl+V がブラウザの貼り付けで、許可を求めずに画像も文字も届く。アプリがクリップボードを読むと、読み取りの許可を断った開発者は Ctrl+V で文字も貼れなくなる。macOS の Ctrl+v はブラウザの貼り付けにならないので、アプリが読むしかない
採らなかった案: どの端末でもアプリがクリップボードを読む (Windows と Linux で許可を求めることになり、断ると貼れなくなる)

- 端末が macOS かは、ブラウザが返すプラットフォームの名前で決める。安全なオリジンかは、ブラウザの判定 (`isSecureContext`) で決める
- Normal とビジュアルの Ctrl+v は、Vim の矩形選択のままにする
- macOS でクリップボードを読めたとき、画像があれば画像だけをすべて上げ、文字は入れない。画像が無く文字があれば、文字をカーソルの位置に入れる
- 開発者がクリップボードの読み取りを許可しなければ、お知らせ「クリップボードを読めませんでした。ブラウザで、このページにクリップボードの読み取りを許可してください」を error で出す
- クリップボードに画像も文字も無ければ、お知らせ「クリップボードに貼り付けられるものがありません」を出す
- ブラウザの貼り付けで届いた画像も、Ctrl+v で読んだ画像と同じに上げる
- 上げるときは `POST /api/conversations/:id/images` を使い、画面のサーバーがファイルに保存する。返った ID を、開いている入力欄の画像の末尾に足す。会話の指示の入力欄では、続けて書きかけを保存する
- 画像を受け付けない入力欄 (worktree の名前の入力など) では、クリップボードの文字だけを入れる。画像しか無ければ、お知らせ「この入力欄には画像を添えられません」を出す
- 書きかけと届く前の指示には、画像の ID の配列を持つ (DESIGN.md「データスキーマ」)
- 指示を届けるとき、ランナーは画像を読み、指示の文と同じ 1 通に付けて AI に送る (BR-008)

#### 入力欄で確かめて外す

開いている入力欄に画像があれば、本文の下に縮小を貼った順に並べ、左上に 1 から始まる番号を付ける。見た目は `features/buffer-ui.md`「入力欄」に従う。縮小は、本文と同じ入力欄の中の「画像の段」として、キーで選んで外せる。キーは既定の割り当てで、動作の名前と変え方は `features/buffer-ui.md`「キーの割り当て」の `prompt-images` の行に従う。

| 場所 | キー | 起きること |
| --- | --- | --- |
| 入力欄の本文 (Normal) | `Ctrl+w j` | 画像の段へ移り、最後に貼った画像を選ぶ。画像が無ければ何もしない |
| 画像の段 | `h` / `l` | 左 / 右の画像を選ぶ。端では止まる |
| 画像の段 | `d` | 選んだ画像を外す。お知らせ「画像 <番号> を外しました」を出す。残りの縮小は詰めて番号を振り直し、同じ位置の画像を選ぶ (最後の画像を外したときは、1 つ左の画像を選ぶ)。画像が無くなれば本文の Normal へ戻る |
| 画像の段 | Enter | 選んだ画像を、元の大きさでブラウザの新しいタブに開く |
| 画像の段 | `Ctrl+w k`、Esc、Ctrl+[ | 本文の Normal へ戻る |
| 画像の段 | `i` | 本文の Insert へ戻る |

- 選んだ画像には、accent の 2px の枠を付ける。画像の段にいるあいだ、ステータス行のモードは「IMAGE」とする
- 画像の段では、ウィンドウを移る動作 (`win.*`) とコマンド行は、本文の Normal と同じに呼べる。`win.up` だけは本文へ戻る動作になる。ほかのキーは何もしない
- 画像の段にいるあいだは、キーを受け取る場所を本文から画像の段へ移す。本文に文字は入らず、IME の変換中のキーには何もしない
- 入力欄の外へ移ったとき (マウスで主のウィンドウを押した、`win.left` で左のウィンドウへ移ったなど) は、画像の段を抜ける。入力欄へ戻ると、本文の Normal になる
- 選んでいる画像は画像の ID で覚える。別の端末の保存で画像が変わっても、選んでいる画像が残っていれば選び続ける。消えていれば同じ位置の画像を選び、画像が無くなれば本文の Normal へ戻る
- 外す画像の対象は、開いている入力欄ごとに次の表のとおりである。`:images clear` (貼った画像をすべて外す) も同じ対象に効く。画像を貼れる入力欄が開いていなければ、`:images clear` はエラーのお知らせ「画像を貼れる入力欄を開いてから使ってください」を出す

| 開いている入力欄 | 外す画像 | 外したことが残るとき |
| --- | --- | --- |
| 会話の指示の入力欄 | 書きかけの画像 | すぐに書きかけを保存する |
| 届く前の指示を ↑ で呼び出して直している入力欄 | 直している指示の画像。書きかけの画像は変わらない | 直した内容を保存したとき (「届く前の指示を入力欄で直す」) |
| 右のウィンドウのスレッドの入力欄 | そのスレッドの書きかけの画像 | すぐに書きかけを保存する |

- 外す前の確認は出さない。外した画像は、貼り直せば戻るためである
- 外しても、画像のファイルは消さない。ファイルは会話を削除するときに消える (`features/conversation-lifecycle.md`)
- 書きかけの画像を外す操作は、書きかけの添付の編集として扱う。保存と端末をまたぐ扱いは「書きかけの入力と未送信」、取り消した指示を戻した直後の制限は「指示を届ける規則」に従う
- 縮小を読み込めない画像 (復元のあとでファイルが無い画像) は、縮小の代わりに「見つかりません」の枠を出す。選んで `d` で外せる。送ると、下の「見つからないとき」のとおりに断られる

決定: 画像は、入力欄の画像の段で選んで `d` で外す
理由: 縮小を見ながら外す画像を選べる。番号をコマンドに打つより、Vim の操作に近い
採らなかった案: コマンド `:images delete <番号>` で外す (縮小の番号を読んでから打ち直す手間がかかる)

#### 見つからないとき

- 画像のファイルが無くなることは、復元のあとに起こる (`features/operations.md`)
- 送る指示の画像のファイルが無いときは、送らずに 400 `invalid_input` と「画像が見つかりません。貼り直してください」を返す
- 番の終わりに届ける預かった指示に見つからない画像があっても、本文か有効な画像が残るときは、見つからない画像だけを外して届ける。お知らせ「画像 n 件が見つからないため、外して届けました」を info で出す
- 本文も有効な画像も無いときは AI を呼ばず、届く前の指示を画像の ID とともに残す。お知らせ「画像が見つからないため、指示を届けられませんでした。画像を添付し直して、もう一度送ってください。」を error で出す
- 発言の「画像 n 件」の行は、ファイルが無い画像の数を「(見つかりません m 件)」として添える。数はイベントの API の応答で画面のサーバーが付ける

#### ツールの結果の画像

ツールの結果に画像のブロックがあれば、ランナーは画像をファイルに保存し、記録には画像の ID だけを残す (BR-104)。記録の文字には 64 KiB の上限があり、画像を文字のまま残すと切れて表示できないためである。保存の規則と記録の形は `features/runtime.md`「Agent SDK のメッセージからの写し方」に従う。

- 会話には、ツールの行と「⎿ <結果の要約>」の行の下に、保存できた画像ごとに「画像 <k> / <n> (Enter で元の大きさで開く)」の行を出し、その行の下に画像を出す。<n> は保存できた画像の数である
- 画像は、主のウィンドウの幅から 2rem を引いた幅と、高さ 16rem に収まるように、縦横比を保って縮める
- 行で Enter を押すと、`GET /api/conversations/:id/images/:imageId` をブラウザの新しいタブで開く
- 保存できなかった画像 (形式や大きさが対象外、書き込みの失敗) があれば、画像の行の後に「画像 <m> 件は保存できなかったため表示できません」の行を出す
- 画像を読み込めない (復元のあとでファイルが無い) ときは、画像の代わりに「画像が見つかりません」を出す
- 記録に画像の ID を持たないツールの結果は、画像を文字で残した結果も含め、記録の文字のまま出す
- ツールの結果の画像は、会話を削除するまで残す。issue の会話は削除できないので、issue の会話の画像は消えずに溜まる

決定: ツールの結果の画像を、自動では片づけない
理由: 画像は会話の記録の一部で、閉じた会話や完了した issue を開き直したときにも見えてほしい。使うのは開発者 1 人で、スクリーンショット 1 枚は多くても数 MB である
採らなかった案: issue の完了や取り下げのときに消す (後から記録を読み返したときに画像が見えなくなる)

### AI の実行の設定

- 会話の実行を開くとき、ランナーは次を渡す。再開するたびに同じものを渡す (DESIGN.md「既知の制約」)
  - 会話の `cwd` と追加の読み取りディレクトリ。追加する条件は `features/recap.md`「会話の AI が一覧を読む」に従う
  - プロジェクトのモデルと許可の扱い。値の読み方は `features/project-settings.md` が決める
  - アプリのツール (`features/issue.md`「AI に渡すツール」)
  - 追加の指示。`features/issue.md`「issue の扱いの追加の指示」の文と、`features/recap.md`「会話の AI が一覧を読む」の文を、どの会話の実行にも渡す
- ユーザー設定 (`~/.claude` の skills、プラグイン、CLAUDE.md、hooks) は、端末の Claude Code と同じに読み込ませる (DESIGN.md「AI の実行の作り」)
- Agent SDK の会話の識別子は、アプリの会話 ID と分けて持つ。通常の新規会話ではアプリが UUID を作って実行に渡し、`init` を受けてから `conversations.session_id` に保存する。分岐で得た識別子は成立済みとして保存する。保存と再開の規則は、`features/runtime.md`「Agent SDK を包む Port」に従う

## API

DESIGN.md「API 一覧」のうち本機能の分を書く。エラーの形と共通のコードは DESIGN.md「横断規約 > エラー応答」に従う。入出力の Zod のスキーマは `src/shared/conversation/api.ts` に置く。

### POST /api/conversations

会話を始める。指示は含めず、空の会話を作る。

```json
{ "projectId": "01J...", "workspace": { "kind": "project" } }
```

`workspace.kind` は `project` (プロジェクトのディレクトリ) / `new_worktree` (新しい worktree を作る。`name` は省略できる) / `worktree` (既存の worktree。`worktreeId` が要る) とする。

- 201: `{ "conversation": <会話の状態> }`。`kind` は `chat`、`run_state` は `idle`
- 404 `not_found`: プロジェクトか worktree が無い。登録を解除したプロジェクトも含む
- 500 `worktree_failed`: worktree を作れなかった。`message` に git の失敗の要約を入れる

### GET /api/conversations/:id

会話の状態を返す。

```json
{
  "conversation": {
    "id": "01J...", "projectId": "01J...", "projectName": "shop-api", "kind": "chat",
    "issueId": null, "parentConversationId": null, "title": "予約 API の壁打ち",
    "cwd": "/Users/.../shop-api", "worktree": null,
    "runState": "usage_limited", "stopReason": "usage_limit", "resetsAt": 1764140400000,
    "lastSeq": 128, "lastReadSeq": 120, "lastPosition": 96, "closedAt": null
  },
  "draft": { "text": "在庫の", "images": [], "updatedAt": 1764137000000, "updatedBy": "01J...タブ" },
  "queue": [{ "id": "01J...", "text": "BOM 付きのときも確かめて", "images": [], "position": 1, "stockItemId": null, "clientId": "01J...", "createdAt": 1764136000000 }],
  "pendingAnswers": { "questionSeq": 121, "answers": { "0": { "choices": ["A (推奨): 1 分ごとの定期処理で戻す"], "text": null } } },
  "pendingPermission": null,
  "commands": [{ "name": "/dev-spec", "description": "設計ループ。..." }]
}
```

- `worktree` は `{ "id", "name", "branch" }` か null
- `pendingPermission` は `{ "requestId", "seq", "toolName", "summary" }` か null
- `queue` の `stockItemId` は、ストックから 1 件ずつ預けた指示の ID である。ほかは null とする
- 複数のストックをまとめて預けた指示は `deliveryContext.stockIds` に元の ID を持つ。`deliveryContext.original` は、開発者の本文・画像・相談の範囲を持つ。取り消しと再送は「指示を届ける規則」に従う
- `queue` の `clientId` は、入力欄から預けた指示の `clientMessageId` である。ストックから預けた指示では null
- 404 `not_found`

### GET /api/conversations/:id/events

`after` (この `seq` より後) と `limit` (既定 2,000、上限 2,000) で範囲を指定する。

- 200: `{ "events": [{ "seq": 1, "type": "...", "payload": {}, "createdAt": 0 }], "lastSeq": 128, "hasMore": false }`
- イベントの `type` と `payload` の形は `features/runtime.md` が正本である
- `user_message` のイベントには、ファイルが無い画像の数を `missingImages` として足して返す。無ければ 0

### POST /api/conversations/:id/messages

```json
{ "text": "在庫の引き当ても同じ API でやりたい。", "images": ["01J...画像"], "mode": "send", "clientMessageId": "01J..." }
```

- `mode` は `send` (作業中なら預ける) / `interrupt` (割り込む) とする
- `stockIds` を指定すると、同じ会話のストックの指示を選んで本文の前に添える。選んだ指示と本文は同じ受付で確定する
- `preserveDraft: true` を指定すると、指示を受け付けても書きかけを消さない。続きを依頼するときと、取り消した指示を戻すときに指定する (`features/work-monitor.md`)
- 取り消した指示の復帰では、通常の送信による下書き消去を抑える `preserveDraft: true` と、`restoreDraft` を付ける。`expected` は確認した書きかけ、`replacement` は戻した分を除いた書きかけである
- `restoreDraft` があれば、ランナーは下書きの時刻、書き手、本文、添付、相談の範囲を比較する。照合と下書きの更新を、指示の受付と同じトランザクションで行う
- 相談を送るときの `timeline_comments` と `timeline_anchors` は `features/work-monitor.md`「相談コメントの保存と抽出」に従う
- `clientMessageId` はタブが送信ごとに作る ULID とする。画面のサーバーは判定せず、ランナーへ `client_id` として渡す
- ランナーは、同じ会話で同じ `client_id` が 10 分以内に届いたら、何もせずに初回の結果を返す。届く前の指示の `client_id` と、`user_message.client_receipts` に残した受付時刻・初回の結果で判定する。`client_ids` と `queued_ids` は、1 通にまとめた指示の番号の一覧として残す。詳しい規則は、`features/runtime.md`「画面のサーバーからランナーへの操作」に従う
- `text` が空で画像も無いときは、預かった指示が残っていれば「届く前の指示を送る」として扱う。`mode` が `interrupt` で AI が作業中なら、AI を止めてから預かった指示だけを 1 通にして届ける
- 202: `{ "result": "delivered" | "queued", "queueItem": <届く前の指示> | null }`
- 400 `invalid_input`: 文も画像も預かった指示も無い。画像が 20 枚を超える。画像のファイルが無い
- 409 `conflict`: issue の担当でない段階の会話に送った (「指示を届ける規則」)。`stockIds` に指定した指示が対象の会話に無いか、送信できる状態にない場合も同じ応答を返す。復帰の `expected` と保存済みの書きかけが違えば、保存済みの書きかけを残す
- 500 `worktree_failed`: issue の段階の worktree を作れなかった。`retryStageWorktree` で作り直せなかったときと、merge の後の直しで新しく作れなかったとき (`features/pr-review.md`) が当たる
  - 開発者の指示は届けず、`user_message` も書かない。書きかけの入力 (`drafts`) は消さずに残し、`message` に git の失敗の要約を入れる
- 503 `runner_unavailable`: ランナーにつながらない。画面は未送信として残す
- 閉じた会話に送ったときは、ランナーが受け付けたあとに会話を開き直す。受け付けなければ閉じたまま残す (BR-096、`features/conversation-lifecycle.md`「開き直す (再開)」)
- issue の会話に送ったときは、届ける前に `flow` の判定を通す (BR-098、BR-099。「指示を届ける規則」)

### POST /api/conversations/:id/stop

- 202: `{ "runState": "stopped" }`。画面はお知らせ「<送り先> の AI を止めました。作業は保存され、指示待ちになります」を出す (「開発者の操作と画面に起きること」)
- 409 `conflict`: AI が作業中 (`working` / `waiting_answer` / `waiting_permission`) ではない。`message` は「止める AI がありません」とする

### POST /api/conversations/:id/resume

- 202: `{ "runState": "working" }`
- 409 `conflict`: 状態が `stopped` (`restarted`)・`failed`・`usage_limited` のどれでもない
- 409 `conflict`: issue の担当でない段階の会話を再開しようとした (「指示を届ける規則」)
- 500 `worktree_failed`: `retryStageWorktree` で worktree を作り直せなかった。`resumed` は書かず、会話は `failed` のまま残す。`message` に git の失敗の要約を入れる
- 閉じた会話の再開は、ランナーが受け付けたあとに会話を開き直す (`features/conversation-lifecycle.md`「開き直す (再開)」)

### PUT /api/conversations/:id/draft

```json
{ "text": "在庫の", "images": [], "clientId": "01J...タブ", "editedAt": 1764137000000 }
```

- 相談を含む書きかけには `timeline_anchors` を付ける。保存した値はこの応答と会話の取得 API の `draft` で返す
- `editedAt` は、そのタブで最後に編集した時刻 (Unix ミリ秒) である。置き換えたときは `drafts.updated_at` に書く
- 200: `{ "draft": { "text", "images", "updatedAt", "updatedBy" }, "applied": true }`。文が空で画像も無ければ書きかけを消し、`draft` は null を返す
- `editedAt` が保存済みの `updatedAt` 以前なら置き換えず、`applied` を false にして保存済みの `draft` を返す
- 復帰の応答を待つ間に編集した書きかけを保存するときは、復帰が確定した時点の書きかけを `expectedDraft` に付ける。保存済みの行が違っていれば 409 `conflict` を返す
- 同じ内容・時刻・書き手がすでに保存されている場合は、その結果を `applied: false` で返す
- この保存の応答が途切れたら、画面は送信済みの要求を保ち、そのまま再試行する。保存を確認してから、その行を前提に後続の追記を保存する
- 応答を待つ間に閉じるなどして次の保存が待っていれば、一度だけ自動で再試行する。再試行の応答も途切れた場合は、次の保存や接続の再開まで待つ
- 400 `invalid_input`: 文が 100,000 文字を超える

### PATCH /api/conversations/:id/queue/:itemId

- 本文: `{ "text": "...", "images": [] }`。相談を編集した場合は `timeline_anchors` も送る。本文の位置を特定できない旧形式の相談を改稿した場合は 409 `conflict` を返し、預けた指示を保つ
- まとめた指示の前置きと引用を保ち、開発者の本文を編集する。前置きや引用の範囲が変わったときは 409 `conflict` を返す
- 200: `{ "queueItem": <届く前の指示> }`
- 404 `not_found`: もう届いたか、取り消された。画面の動きは「届く前の指示を入力欄で直す」に従う

### DELETE /api/conversations/:id/queue/:itemId

- 204。404 `not_found` は PATCH と同じ
- ストックと書きかけの更新は「指示を届ける規則」に従う

### PUT /api/conversations/:id/answers

```json
{ "questionSeq": 121, "answers": { "0": { "choices": ["A (推奨): 1 分ごとの定期処理で戻す"], "text": null }, "1": { "choices": [], "text": "変えられるようにして" } } }
```

- `answers` のキーは、その質問のイベントの中の何問目か (0 から) とする
- 200: `{ "pendingAnswers": <保存した回答> }`
- 409 `conflict`: `questionSeq` が、いちばん新しい未回答の質問ではない

### POST /api/conversations/:id/answers/send

画面のサーバーは、開発者が確認した質問番号と回答の内容を照合してから送る。

- 全問に答えたときの本文は `{ "questionSeq": 121, "confirmUnanswered": false }` とする
- 未回答のまま送ることを確認したときは `confirmUnanswered` を true にし、確認を開いた時点の回答を `confirmedAnswers` に入れる。値の形は `PUT /api/conversations/:id/answers` の `answers` と同じである
- サーバーは `questionSeq` を、保存済みの回答と現在の未回答の質問の両方に照合する。質問番号を省略して送れるのは、その会話で最初の選択式の質問に全問答えたときだけである
- 202 は `{ "result": "answered" | "delivered" | "queued" }` を返す。`delivered` と `queued` は、質問を待たなくなった会話に普通の指示として送ったときに返す
- 409 `unanswered_questions` は、答えていない質問があり、`confirmUnanswered` が false のときに返す
- 409 `answers_changed` は、確認時の質問番号や回答を省いたとき、または受付までに保存済みの回答が変わったときに返す。未回答の件数が同じでも、選択肢や文章が変われば再確認が要る
- 409 `conflict` は、送る前の回答が無い、質問番号が合わない、または回答の受付までに AI が別の応答を始めたときに返す。2 回目以降の選択式の質問で番号を省いた場合も、このエラーを返す
- 503 `runner_unavailable` は、画面のサーバーだけを更新し、未回答付き送信の照合にランナーが対応していないときにも返す。送る前の回答を残し、ランナーの更新を案内する
- `unanswered_questions` または `answers_changed` を受け取ったとき、同じ画面で同じ質問を開いていれば、保存済みの回答を読み直す。画面は内容を確かめてからもう一度送るよう知らせ、次の送信操作で最新の未回答件数を出す
- 閉じた会話に送ったときは、ランナーが受け付けたあとに会話を開き直す (`features/conversation-lifecycle.md`「開き直す (再開)」)

### POST /api/conversations/:id/images

- 本文は画像のバイト列そのもので、`Content-Type` に `image/png` / `image/jpeg` / `image/gif` / `image/webp` を指定する
- 201: `{ "image": { "id": "01J...", "mediaType": "image/png", "bytes": 120345 } }`
- 400 `invalid_input`: 形式が違う。5 MB を超える

### GET /api/conversations/:id/images/:imageId

- 貼り付けた画像とツールの結果の画像を、どちらも返す。ファイルの引き方は `features/runtime.md`「書くプロセスの分担」に従う
- 200: 本文は画像のバイト列そのもので、`Content-Type` はファイルの拡張子から決める。同じ ID の画像は変わらないので、`Cache-Control: private, max-age=31536000, immutable` を付ける
- 404 `not_found`: 会話が無い。ID が ULID の形でない。ファイルが無い

### POST /api/conversations/:id/permissions/:requestId

- 本文: `{ "decision": "allow" | "deny" }`
- 202: `{ "runState": "working" }`
- 409 `conflict`: その確認はもう答えたか、AI が待っていない

## エッジケースの決定

1. 空・最小データ: 指示を送っていない会話は、本文に「i で指示を書いて送ると、AI が作業を始めます。」の 1 行だけを出す。文も画像も無い送信は、預かった指示が無ければ送らず、入力欄を開いたままにする
2. 上限・境界値: 画像は 1 枚 5 MB、1 通に 20 枚まで。ツールの結果の画像も 1 枚 5 MB、1 件の結果に 20 枚までを保存し、超えた分は保存できなかった画像として数える。書きかけと指示の文は 100,000 文字まで。差分は 25 行を超えると畳む。イベントの読み込みは 1 回 2,000 件で、会話の長さに上限は設けない
3. エラー時に利用者へ見えるもの: 送信・保存・回答・停止の失敗は、`message` をエラーのお知らせに出す。Ctrl+v でクリップボードを読めないときは、理由をお知らせに出す (「貼り付けた画像」)。ツールの結果の画像を保存できなくても番は止めず、会話に保存できなかった件数の行を出し、ログに理由を残す。送信の失敗では入力欄の中身を残し「未送信」と出す。届く前の指示を直した内容を保存できなかったときは、404 を除いて、その指示に留まる (「届く前の指示を入力欄で直す」)。worktree を作れなかったときは会話を作らず、理由をお知らせに出す
4. 並行操作・二重実行: 送信の 2 回目は、ランナーが同じ `client_id` で見分けて無視する。届く前の指示の取り消しと配達が重なったら、先に通った方だけが効き、取り消しは 404 になる。直している指示が先に届くか取り消されたら、書きかけに戻る (「届く前の指示を入力欄で直す」)。止める操作が二重に届いたら 2 回目は 409 にする。2 つの端末で回答を保存したら後から届いた方を残す。書きかけは後から書いた方を残す。2 つの端末で貼った画像を外したときも同じである。同じ会話を動かす実行は 1 つだけで、ランナーは会話ごとに操作を順に処理する
5. 再表示時の整合: 画面を開くたびに、会話の状態とイベントを API で読み直す。配信が途切れたら、覚えている最後の `seq` から読み直す。書きかけ・届く前の指示・送る前の回答は、サーバーの値で表示する
6. 表示の寿命: 「未送信」の表示は、送信に成功するか入力欄を空にすると消える。「✓ 選んだ (まだ送っていない)」は送るか AI が次の応答を始めると消える。止まった理由の行は会話の記録として残る。書きかけの区画は、その発言の記録か番の終わりが届くと消える。置き換えのお知らせは 4 秒で消える。欄の名前「預けた指示を直す (k / n 件目)」は、書きかけに戻るか入力欄を閉じると消える
7. 送る前のデータ: 書きかけ・届く前の指示・送る前の回答はサーバーに置き、送るか開発者が消すまで残す (P1)。会話を閉じても残る (BR-097)。送る前の回答は AI が次の応答を始めると消える。届く前の指示を取り消すと、ストックか書きかけに戻る。指示を直しているあいだも、書きかけはサーバーに残ったままで、入力欄の内容を書きかけとして保存しない
8. 状態の移り変わり: 「状態と止まった理由」の表のとおり。止まった会話に指示を送ると `working` に移る。再開は `stopped` (`restarted`)・`failed`・`usage_limited` からだけできる
9. 自動で進むこと: 番が正常に終わったときの預かった指示の配達と、利用枠が戻ったときの再開だけを自動で行う。自動フローの会話は、一時停止のあいだと、その段階を自動で処理する段階から外しているあいだは、枠が戻っても再開しない。失敗の再開、未送信の送信、止めたあとの預かった指示の配達は自動では行わない (P2)
10. 端末と画面をまたぐこと: 書きかけ・届く前の指示・送る前の回答・会話の状態は、サーバーの値をどの端末でも同じに見せる。入力欄が開いているか、カーソル、差分の畳みの開閉は、タブごとに持つ (P3)。貼った画像は書きかけと一緒にどの端末でも同じに見え、縮小の番号は書きかけの画像の並びで決まる
11. 並びと数え方: 会話の行は `seq` の順。届く前の指示は書いた順で、1 通にまとめるときもこの順。入力欄の ↑ は新しい指示から古い指示へたどり、k は古い方から数える。作業中の表示の番の経過と工程の経過は `features/work-monitor.md` の起点から数える。「回答をまとめて送る (n / m 件)」の n は答えた質問の数、m は質問の数。貼った画像の番号は貼った順に 1 から数え、ツールの結果の画像の「<k> / <n>」は結果の中の画像の順に数える

- （US-014）の単体のテストは、書きかけの文字が末尾に逐次出て、発言の記録が届くと置き換わることも確かめる。ツールの行の Enter で開く先 (ファイル、issue) も同じテストで確かめる
- （US-014）の単体のテストでは、AI の発言の行だけが Markdown として整い、発言をまたいで装飾が及ばないことも確かめる。表は、同じ列のセルが同じ幅で出ることと、カーソルの行ではソースのまま出ることを確かめる。Mermaid の図は、発言の中の閉じたブロックにだけ出ることと、書きかけでフェンスが閉じたときに出ることを確かめる
- 「指示を届ける規則」のストックの `sent_seq` と戻しは、（US-015）の届く前の指示の結合のテストで確かめる。`flow` の判定は `features/design-review.md` と `features/pr-review.md` のテストが持つ
