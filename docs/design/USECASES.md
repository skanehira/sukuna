# ユースケース記述

- 種別: ユースケース記述

各ユースケースの末尾に受け入れ基準を置く。受け入れ基準は「どんなときに、何をすると、どうなるか」を 1 文で書き、先頭にその基準が満たすストーリーの番号を付ける。チェックボックスは一覧の書式で、印は付けない。ユースケースの完了は、そのユースケースの親 issue の子 issue がすべて close したことで判定する。

## 用語

| 用語 | 意味 |
|------|------|
| 判断待ち | 開発者が判断しないと作業が進まない状態。設計の承認、AI の質問、許可の確認、merge 前の確認、失敗か利用枠切れか CI の失敗による停止を含む。応答の最後に質問が書かれた会話も含む |
| 指示待ち | 作業が一区切りし、次の指示を待っている状態。質問なしで応答が終わった会話と、開発者が止めたエージェントを含む |
| 停止中 | issue の状態の 1 つ。AI の質問、失敗、利用枠切れ、CI の失敗、merge 前の確認、依存先の取り下げのどれかで進められず、開発者の判断を待って止まっている。一覧では判断待ちのセクションに出る |
| 未読 | 判断待ちか指示待ちのうち、開発者がまだ回答を読んでいないもの |
| 作業中 | AI が作業している状態 |
| 一覧 | 全プロジェクトの会話と issue を、判断待ち・指示待ち・作業中のセクションに分けて並べた画面。下書き、依存先を待つ issue、完了した issue は載せない |

## 挙動の方針

全ユースケースに効く、細部の挙動の決め方。各ユースケースのビジネスルールは、この方針から導く。

| ID | 方針 |
|----|------|
| P1 | 送る前のもの（書きかけの入力、ストック、送る前の回答、届く前の指示）はサーバーに置き、端末の間で共有する。送るか自分で消すまで残す |
| P2 | 開発者が始めた作業の続きは自動で進める。開発者が書いた内容を送るのは、開発者の操作だけにする |
| P3 | 読んだ・決めたという事実は端末の間で共有する。画面の見え方（カーソル、開いている表示）はブラウザのタブごとに持つ |
| P4 | 開発者の対応が要る変化は、どこで起きても一覧と通知に出す。いま見ているものには出さない |
| P5 | AI に直しを頼むと issue は作業中の状態に戻り、直し終えると元の確認に戻る |
| P6 | 取り返しのつかない操作は、PC では確認、スマホでは 5 秒の猶予を挟む。猶予のあいだは実行しない |

## UC-001: 状況をつかんで、次に対応する作業を選ぶ

### 事後条件

|---|----------|-----------|
| 1 | 開発者 | 一覧を開く |
| 2 | システム | 全プロジェクトの会話と issue を、判断待ち・指示待ち・作業中の順のセクションに分けて表示する。未読の行には未読の印を付ける |

| 4 | システム | 作業中の行に、今の工程、その工程の経過時間、最後にしたことを表示する |

|---|----------|-----------|

## UC-002: 会話で AI に作業を頼む

### 概要
| 項目 | 内容 |
|------|------|
| ユースケースID | UC-002 |
| ユースケース名 | 会話で AI に作業を頼む |
| 主アクター | 開発者 |
| 副アクター | AI (Claude Code) |
| トリガー | やりたいことができたとき、AI の返事に答えるとき |

### 事前条件
- プロジェクトが 1 つ以上登録されている

### 事後条件
- AI が応答を終え、会話が判断待ちか指示待ちになっている

### 正常系フロー
| # | アクター | アクション |
|---|----------|-----------|
| 1 | 開発者 | プロジェクトを選んで会話を始める。または既存の会話を開く |
| 2 | 開発者 | 入力欄を開き、指示を書く。スキルは候補から選び、画像は貼り付ける |
| 3 | 開発者 | 送信する |
| 4 | システム | 指示と、貼り付けた画像を AI に送る |
| 5 | AI | 作業する。呼び出されたスキルは、端末の Claude Code と同じ手順で進める |
| 6 | システム | 発言、ツールの実行、差分を、種類の分かる形で順に表示する |
| 7 | AI | 選択式の質問を出す |
| 8 | 開発者 | 選択肢を選ぶか、文章を書いて答える |
| 9 | AI | 続きを行い、応答を終える |
| 10 | システム | 応答の最後に質問があれば会話を判断待ちに、無ければ指示待ちにする |

### 代替フロー
#### A: worktree を作って始める（ステップ1の代替）
| # | アクター | アクション |
|---|----------|-----------|
| 1a | 開発者 | 会話を始めるときに、worktree の作成か、既存の worktree を選ぶ |
| 1b | システム | 作成を選んだときは新しい worktree を作り、会話を選んだ worktree の中で動かす |

#### B: 作業中に次の指示を送る（ステップ5の途中）
| # | アクター | アクション |
|---|----------|-----------|
| 5a | 開発者 | AI が作業中に、次の指示を送る |
| 5b | システム | 指示を預かり、今の作業が終わってから AI に届ける |
| 5c | 開発者 | 届く前に、預けた指示を取り消すか編集する |

#### C: 作業を止めて割り込む（ステップ5の途中）
| # | アクター | アクション |
|---|----------|-----------|
| 5a | 開発者 | 割り込みを選び、指示を書いて送る |
| 5b | システム | AI の作業を止め、届く前の指示があれば新しい指示の前に付けて、すぐに届ける |

#### D: 画面を閉じる（ステップ5の途中）
| # | アクター | アクション |
|---|----------|-----------|
| 5a | 開発者 | 画面を閉じる |
| 5b | AI | 作業を続ける |
| 5c | システム | 開き直したときに、続きを表示する |

#### E: 別の会話へ切り替える（ステップ2の途中）
| # | アクター | アクション |
|---|----------|-----------|
| 2a | 開発者 | 入力の途中で、別の会話へ切り替える |

#### F: 許可の確認に答える（ステップ7の代替）
| # | アクター | アクション |
|---|----------|-----------|
| 7a | AI | 許可の扱いを既定から変えたプロジェクトで、ツールの実行の許可を求める |
| 7b | システム | 許可の確認を表示し、会話を判断待ちにする |
| 7c | 開発者 | 許可するか、拒否する |
| 7d | AI | 答えに従って続きを行う |
